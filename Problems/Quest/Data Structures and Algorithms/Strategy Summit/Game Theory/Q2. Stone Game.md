# Intuition

This problem can be solved using **dynamic programming** based on game theory. At each turn, a player wants to **maximize their own score advantage** over the opponent. Since both players play optimally, we can define a recursive relationship representing the *best possible score difference* the current player can achieve from any given subarray of piles.

Interestingly, there's also a well-known mathematical shortcut for this specific problem (explained at the end), but let's first walk through the general DP approach, which works for any similar game — even if the special conditions here didn't guarantee a simple answer.

---

# Approach

## Step 1: Define the DP state

Let `dp[i][j]` represent the **maximum score difference** (current player's score minus opponent's score) achievable by the player whose turn it is, when only piles from index `i` to `j` remain.

## Step 2: Base case

When there's only one pile left (`i == j`):
```text
dp[i][i] = piles[i]
```
(The player takes that pile entirely.)

## Step 3: Transition

For a range `[i, j]`, the current player chooses either:
- The pile at the start (`piles[i]`), leaving the opponent with the range `[i+1, j]`
- The pile at the end (`piles[j]`), leaving the opponent with the range `[i, j-1]`

Since whatever the opponent gains becomes a *loss* relative to us, we subtract their optimal result:

```text
dp[i][j] = max(
    piles[i] - dp[i+1][j],
    piles[j] - dp[i][j-1]
)
```

## Step 4: Final answer

If `dp[0][n-1] > 0`, it means Alice (playing first) achieves a strictly positive score advantage, so **Alice wins**.

## Step 5: Fill the DP table

We iterate by increasing subarray length, filling `dp[i][j]` for all pairs where `j - i` increases from `0` to `n - 1`.

---

# Complexity

- **Time complexity:** 
$$O(n^2)$$
We fill an `n x n` DP table, computing each cell in `O(1)`.

- **Space complexity:**
$$O(n^2)$$
For the DP table (can be optimized to `O(n)` using rolling arrays, but `O(n^2)` is sufficient given `n ≤ 500`).

---

# Code

```typescript
function stoneGame(piles: number[]): boolean {
    const n = piles.length;
    const dp: number[][] = Array.from({ length: n }, () => new Array(n).fill(0));

    // Base case: single pile.
    for (let i = 0; i < n; i++) {
        dp[i][i] = piles[i];
    }

    // Fill by increasing subarray length.
    for (let length = 2; length <= n; length++) {
        for (let i = 0; i + length - 1 < n; i++) {
            const j = i + length - 1;
            dp[i][j] = Math.max(
                piles[i] - dp[i + 1][j],
                piles[j] - dp[i][j - 1]
            );
        }
    }

    return dp[0][n - 1] > 0;
};

```

# Example Walkthrough

## Example 1

```text
piles = [5, 3, 4, 5]
```

Building the DP table (score difference for the current player):

- Base cases: `dp[0][0]=5, dp[1][1]=3, dp[2][2]=4, dp[3][3]=5`
- Length 2:
  - `dp[0][1] = max(5-3, 3-5) = 2`
  - `dp[1][2] = max(3-4, 4-3) = 1`
  - `dp[2][3] = max(4-5, 5-4) = 1`
- Length 3:
  - `dp[0][2] = max(5-1, 4-2) = 4`
  - `dp[1][3] = max(3-1, 5-1) = 4`
- Length 4:
  - `dp[0][3] = max(5-4, 5-4) = 1`

`dp[0][3] = 1 > 0` → Alice wins.

Output: `true`

# Bonus Insight

There's a well-known mathematical proof that under the given constraints (**even number of piles**, **all positive integers**, **sum is odd**), **Alice always wins** — regardless of the specific pile values!

## Why?

- Alice can strategically choose to always take from either **all even-indexed piles** or **all odd-indexed piles** (whichever sums to more). 
- Since piles alternate in position, Alice can force Bob into a position where he's always forced to give Alice access to the group she wants.
- Because the total sum is **odd**, one of these two groups (even-indexed or odd-indexed) must have a strictly larger sum, guaranteeing Alice's win.

So a valid **O(1)** solution is simply:

```typescript
function stoneGame(piles: number[]): boolean {
    return true;
};

```

> However, the DP solution above is the general-purpose approach that would work even without these special guarantees, and is worth understanding for variations of this problem (e.g., LeetCode's "Stone Game II/III" where the special trick doesn't apply).
