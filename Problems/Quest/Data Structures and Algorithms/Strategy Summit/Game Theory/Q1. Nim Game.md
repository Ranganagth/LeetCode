# Intuition

This is a classic **game theory** problem. With optimal play, the key observation is that whoever faces a heap size that is a **multiple of 4** is guaranteed to lose, no matter what they do — because their opponent can always respond by bringing the heap back down to the next lower multiple of 4.

---

# Approach

Think recursively:
- If `n` is `1`, `2`, or `3`, you can simply take all the stones and win immediately.
- If `n = 4`, no matter how many stones you take (`1`, `2`, or `3`), you leave your opponent with `3`, `2`, or `1` stones respectively — and *they* will take all of them and win.
- If `n` is greater than `4`, you can always remove enough stones (`1` to `3`) to leave your opponent at a multiple of `4`. This forces them into the losing position described above.

By induction, **any heap size that is a multiple of 4 is a losing position** for the player about to move, and any other heap size is a **winning position** (since you can always move to the nearest lower multiple of 4).

So the entire problem reduces to a simple check:

```text
n % 4 !== 0
```

---

# Complexity

- **Time complexity:** 
$$O(1)$$
A single modulo operation determines the result.

- **Space complexity:** 
$$O(1)$$
No extra space is used.

---

# Code

```typescript
function canWinNim(n: number): boolean {
    return n % 4 !== 0;
};

```

# Example Walkthrough

## Example 1

```text
n = 4
```

```text
4 % 4 === 0 → false
```

Output: `false` — matches expected, since every move you make leaves a heap size (`1`, `2`, or `3`) that your friend can fully clear.

## Example 2

```text
n = 1
```

```text
1 % 4 !== 0 → true
```

Output: `true` — you simply take the 1 stone and win immediately.

## Example 3

```text
n = 2
```

```text
2 % 4 !== 0 → true
```

Output: `true` — you take both stones and win.
