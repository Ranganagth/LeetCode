# Intuition

Each child needs at least 1 candy, and any child with a **higher rating than a neighbor** must get **more candies** than that neighbor. This is a classic **two-pass greedy** problem: scan left-to-right to satisfy the "increasing from left" condition, then scan right-to-left to satisfy the "increasing from right" condition, taking the maximum at each position.

---

# Approach

1. **Initialize** a `candies` array with all 1s (minimum requirement)
2. **Left-to-right pass:** If `ratings[i] > ratings[i-1]`, then `candies[i] = candies[i-1] + 1`
3. **Right-to-left pass:** If `ratings[i] > ratings[i+1]`, then `candies[i] = max(candies[i], candies[i+1] + 1)`
4. **Sum all candies** for the final answer

---

# Complexity

**Time Complexity:** $O(n)$ - two linear passes

**Space Complexity:** $O(n)$ - candies array (can be optimized to $O(1)$ with a more complex single-pass approach, but $O(n)$ is clear and simple)

---

# Code

```typescript
function candy(ratings: number[]): number {
    const n = ratings.length;
    const candies = new Array(n).fill(1);
    
    // Left to right: ensure right neighbor gets more if rating is higher
    for (let i = 1; i < n; i++) {
        if (ratings[i] > ratings[i - 1]) {
            candies[i] = candies[i - 1] + 1;
        }
    }
    
    // Right to left: ensure left neighbor gets more if rating is higher
    for (let i = n - 2; i >= 0; i--) {
        if (ratings[i] > ratings[i + 1]) {
            candies[i] = Math.max(candies[i], candies[i + 1] + 1);
        }
    }
    
    // Sum all candies
    let total = 0;
    for (const c of candies) {
        total += c;
    }
    
    return total;
};

```

# Example Walkthrough

## Example 1: `ratings = [1,0,2]`

```
Initial: candies = [1,1,1]

Left-to-right pass:
  i=1: ratings[1]=0 > ratings[0]=1? No
  i=2: ratings[2]=2 > ratings[1]=0? Yes → candies[2]=candies[1]+1=2

candies = [1,1,2]

Right-to-left pass:
  i=1: ratings[1]=0 > ratings[2]=2? No
  i=0: ratings[0]=1 > ratings[1]=0? Yes → candies[0]=max(1,candies[1]+1)=max(1,2)=2

candies = [2,1,2]

Total = 2+1+2 = 5
```

**Output:** `5` ✓

---

## Example 2: `ratings = [1,2,2]`

```
Initial: candies = [1,1,1]

Left-to-right pass:
  i=1: ratings[1]=2 > ratings[0]=1? Yes → candies[1]=2
  i=2: ratings[2]=2 > ratings[1]=2? No (equal)

candies = [1,2,1]

Right-to-left pass:
  i=1: ratings[1]=2 > ratings[2]=2? No (equal)
  i=0: ratings[0]=1 > ratings[1]=2? No

candies = [1,2,1]

Total = 1+2+1 = 4
```

**Output:** `4` ✓

---

# Key Insights

1. **Two-pass strategy handles both directions:** Left-to-right ensures increasing sequences going right are satisfied; right-to-left handles the reverse
2. **Taking the max preserves both constraints:** When both passes suggest a candy count, we need the larger value to satisfy both left and right neighbor comparisons simultaneously
3. **Equal ratings need no extra candies:** Only strictly greater ratings require more candies than neighbors

# Edge Cases

| Case | Input | Output | Explanation |
|------|-------|--------|-------------|
| Single child | `[5]` | 1 | Minimum requirement |
| All equal | `[3,3,3]` | 3 | Each gets 1 candy (no strict inequality) |
| Strictly increasing | `[1,2,3,4]` | 10 | 1+2+3+4=10 |
| Strictly decreasing | `[4,3,2,1]` | 10 | 4+3+2+1=10 |
| Valley pattern | `[1,0,2]` | 5 | Handled correctly by two passes |

> This two-pass greedy approach is the **standard and optimal solution** for this classic candy distribution problem!
