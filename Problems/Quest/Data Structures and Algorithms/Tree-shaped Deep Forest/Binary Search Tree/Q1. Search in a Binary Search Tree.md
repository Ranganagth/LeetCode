# Intuition

Since this is a **Binary Search Tree (BST)**, we can leverage its key property: for any node, all values in the **left subtree** are smaller, and all values in the **right subtree** are larger. This allows us to efficiently navigate to the target value without exploring both subtrees at every step.

**Key insight:** Instead of searching both left and right subtrees like a regular binary tree, we can decide which direction to go based on comparing `val` with the current node's value.

---

# Approach

1. **Base case:** If `root` is null or `root.val === val`, return `root` (found or not found)
2. **Compare values:**
   - If `val < root.val`: search in the **left subtree**
   - If `val > root.val`: search in the **right subtree**
3. **Recurse or iterate** until found or reach a null node

This can be implemented either **recursively** or **iteratively**.

---

# Complexity

**Time Complexity:** $O(H)$
- $H$ is the height of the tree
- $O(log n)$ for balanced BST
- $O(n)$ for skewed BST (worst case)

**Space Complexity:**
- **Recursive:** $O(H)$ for recursion stack
- **Iterative:** $O(1)$ - no extra space needed

# Code

## Solution 1: Iterative Approach (Recommended - $O(1)$ space)

```typescript
function searchBST(root: TreeNode | null, val: number): TreeNode | null {
    let current = root;
    
    while (current !== null) {
        if (current.val === val) {
            return current;
        } else if (val < current.val) {
            current = current.left;
        } else {
            current = current.right;
        }
    }
    
    return null;
};

```

---

## Solution 2: Recursive Approach

```typescript
function searchBST(root: TreeNode | null, val: number): TreeNode | null {
    if (root === null || root.val === val) {
        return root;
    }
    
    if (val < root.val) {
        return searchBST(root.left, val);
    } else {
        return searchBST(root.right, val);
    }
};

```

---

## Solution 3: With Detailed Comments

```typescript
function searchBST(root: TreeNode | null, val: number): TreeNode | null {
    // Base case: reached null (not found) or found the value
    if (root === null || root.val === val) {
        return root;
    }
    
    // BST property: if val is smaller, search left subtree
    if (val < root.val) {
        return searchBST(root.left, val);
    } 
    // If val is larger, search right subtree
    else {
        return searchBST(root.right, val);
    }
};

```

---

## Solution 4: Compact Ternary Version

```typescript
function searchBST(root: TreeNode | null, val: number): TreeNode | null {
    if (!root || root.val === val) return root;
    return val < root.val ? searchBST(root.left, val) : searchBST(root.right, val);
};

```

# Example Walkthrough

## Example 1: `root = [4,2,7,1,3], val = 2`

### Tree Structure

```
        4
       / \
      2 7
     / \
    1 3
```

### Iterative Search Process

```
Start: current = node(4)

Step 1: current.val (4) === val (2)? No
        val (2) < current.val (4)? Yes
        Move to left child
        current = node(2)

Step 2: current.val (2) === val (2)? Yes!
        Return node(2)

Found subtree rooted at node(2):
        2
       / \
      1 3
```

**Output:** `[2,1,3]`

---

## Example 2: `root = [4,2,7,1,3], val = 5`

### Search Process

```
Start: current = node(4)

Step 1: current.val (4) === val (5)? No
        val (5) < current.val (4)? No
        Move to right child
        current = node(7)

Step 2: current.val (7) === val (5)? No
        val (5) < current.val (7)? Yes
        Move to left child
        current = node(7).left = null

Step 3: current === null
        Exit loop, return null
```

**Output:** `[]` (null, represented as empty tree)

# Key Insights

1. **BST property is key:** Only need to explore one subtree at each step, not both
2. **No backtracking needed:** Once we decide direction (left/right), we never need to go back
3. **Efficient pruning:** Eliminates half the remaining tree at each comparison
4. **Iterative preferred:** Avoids recursion stack overhead, especially for skewed trees

---

# Edge Cases

| Case | Input | Output | Explanation |
|------|-------|--------|-------------|
| Value at root | `val = root.val` | root itself | Immediate match |
| Value not in tree | `val` doesn't exist | null | Search reaches null |
| Single node tree | `root = [5], val = 5` | `[5]` | Trivial match |
| Value smaller than all | `val < min` | null | Goes left until null |
| Value larger than all | `val > max` | null | Goes right until null |

---

# Common Mistakes to Avoid

1. **Not leveraging BST property:**
   ```typescript
   // Wrong: searching both subtrees like regular binary tree
   const left = searchBST(root.left, val);
   const right = searchBST(root.right, val);
   return left || right;
   
   // Correct: only search one direction based on BST property
   return val < root.val ? searchBST(root.left, val) : searchBST(root.right, val);
   ```

2. **Forgetting base case for null:**
   ```typescript
   // Wrong: might cause null reference error
   if (root.val === val) return root;
   
   // Correct: check null first
   if (root === null || root.val === val) return root;
   ```

# Recommended Solution

**Use Solution 1 (Iterative)** for:
- $O(1)$ space complexity (no recursion stack)
- Better performance for large/skewed trees
- Avoids potential stack overflow

**Use Solution 2 (Recursive)** for:
- Cleaner, more intuitive code
- Better readability
- Sufficient for balanced trees within given constraints

> Both solutions have the same time complexity and are correct - choose based on your preference for iterative vs recursive style!
