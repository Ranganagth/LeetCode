# Intuition

A word can be "built" character by character only if **every prefix** of that word (including the word minus its last character) also exists in the dictionary. This is essentially checking if there's a **complete chain** from a single character up to the full word.

**Key insight:** If we sort words by length (and lexicographically for ties), we can build up a set of "valid" words incrementally - a word is valid only if removing its last character gives another valid word already in our set.

---

# Approach

1. **Sort the words** first by length, then lexicographically (this ensures shorter prefixes are processed before longer words, and ties are broken correctly)
2. **Use a Set** to track which words can be successfully built
3. **For each word:**
   - If length is 1, it's always buildable (single character)
   - Otherwise, check if `word.slice(0, -1)` (word without last character) exists in our valid set
   - If yes, add current word to the set and check if it's longer than our current answer (or same length but lexicographically smaller)
4. **Return the answer**

---

# Complexity

**Time Complexity:** $O(n log n + n × L)$
- Sorting: $O(n log n)$ where n = number of words
- Building set and checking: $O(n × L)$ where L = average word length

**Space Complexity:** $O(n × L)$
- Set stores all buildable words

---

# Code

```typescript
function longestWord(words: string[]): string {
    // Sort by length first, then lexicographically
    words.sort((a, b) => {
        if (a.length !== b.length) return a.length - b.length;
        return a < b ? -1 : 1;
    });
    
    const validWords = new Set<string>();
    let result = "";
    
    for (const word of words) {
        if (word.length === 1 || validWords.has(word.slice(0, -1))) {
            validWords.add(word);
            if (word.length > result.length) {
                result = word;
            }
        }
    }
    
    return result;
};

```

# Example Walkthrough

## Example 2: `words = ["a","banana","app","appl","ap","apply","apple"]`

### After Sorting

```
Sorted: ["a", "ap", "app", "appl", "apple", "apply", "banana"]
```

### Processing

```
"a": length=1, valid! Add to set. result="a"
"ap": slice(0,-1)="a", in set? Yes. Add "ap". result="ap"
"app": slice(0,-1)="ap", in set? Yes. Add "app". result="app"
"appl": slice(0,-1)="app", in set? Yes. Add "appl". result="appl"
"apple": slice(0,-1)="appl", in set? Yes. Add "apple". result="apple" (length 5)
"apply": slice(0,-1)="appl", in set? Yes. Add "apply". length=5, same as result, but "apple" < "apply" lexicographically, so result stays "apple"
"banana": slice(0,-1)="banan", in set? No. Skip.
```

**Output:** `"apple"`

---

# Key Insights

- **Sorting order is crucial:** Sorting by length then lexicographically ensures we process prefixes before the words that need them, and naturally handles tie-breaking
- **Set lookup is O(1):** Makes prefix checking efficient
- **Single characters are base case:** Always valid starting points for building longer words
