# Intuition

This problem requires finding, for each query, the **leftmost meeting point** where two people can both reach based on an increasing height condition. Key observations:

1. **If Alice and Bob are at the same building**, they're already together (answer = that index)
2. **If one person's building is shorter than the other's**, they can move directly to the taller building
3. **If both buildings have complex height relationships**, we need to find the leftmost building to the right of both positions where the height exceeds both their current heights

**Critical insight:** For the complex case, we need the smallest index `j` beyond both positions where `heights[j] > max(heights[a], heights[b])`. Processing this naively for each query would be $O(n)$ per query, but we can use an **offline approach with a min-heap** to solve all queries efficiently in $O(n log n + q log q)$.

---

# Approach

## Step 1: Categorize Queries

For each query `(a, b)`, ensure `a <= b` (swap if needed):
- **Case 1:** `a === b` → Answer is `a` (same building)
- **Case 2:** `heights[a] < heights[b]` → Answer is `b` (Alice can jump directly to Bob)
- **Case 3:** Otherwise → Need to find leftmost `j > b` where `heights[j] > heights[a]`

## Step 2: Offline Processing with Min-Heap

For Case 3 queries, we defer processing:
1. Group queries by their `b` value (the position after which we need to search)
2. Process buildings left to right (index `i` from `0` to `n-1`)
3. **Before processing index `i`:** Check the min-heap - if the minimum required height is less than `heights[i]`, this query is satisfied! Pop and record answer as `i`
4. **After processing index `i`:** Add all Case 3 queries with `b === i` into the heap (they become "active" starting from `i+1`)

**Why this works:** By processing indices in order and using a min-heap, we always find the **smallest satisfying index** for each query, since we check queries in the exact order buildings appear.

---

# Complexity

**Time Complexity:** $O((n + q) log q)$
- Building categorization: $O(q)$
- Processing each index: $O(1)$ amortized heap operations
- Each query pushed/popped from heap once: $O(log q)$ per operation
- Total: $O(n log q + q log q)$

**Space Complexity:** $O(n + q)$
- Storage for queries grouped by index: $O(q)$
- Heap size: $O(q)$ in worst case
- Answer array: $O(q)$

# Code

```typescript
function leftmostBuildingQueries(heights: number[], queries: number[][]): number[] {
    const n = heights.length;
    const q = queries.length;
    const ans: number[] = new Array(q).fill(-1);
    
    // Group queries by their 'b' index for offline processing
    const queriesByB: Array<Array<[number, number]>> = Array.from(
        { length: n },
        () => []
    );
    
    // Categorize queries
    for (let idx = 0; idx < q; idx++) {
        let [a, b] = queries[idx];
        if (a > b) [a, b] = [b, a];
        
        if (a === b) {
            ans[idx] = a;
        } else if (heights[a] < heights[b]) {
            ans[idx] = b;
        } else {
            // Need to find leftmost j > b with heights[j] > heights[a]
            queriesByB[b].push([heights[a], idx]);
        }
    }
    
    // Min-heap implementation: [requiredHeight, queryIdx]
    const heap: Array<[number, number]> = [];
    
    function heapPush(item: [number, number]): void {
        heap.push(item);
        let i = heap.length - 1;
        
        while (i > 0) {
            const parent = (i - 1) >> 1;
            if (heap[parent][0] <= heap[i][0]) break;
            
            [heap[parent], heap[i]] = [heap[i], heap[parent]];
            i = parent;
        }
    }
    
    function heapPop(): [number, number] {
        const top = heap[0];
        const last = heap.pop()!;
        
        if (heap.length > 0) {
            heap[0] = last;
            let i = 0;
            
            while (true) {
                let smallest = i;
                const left = 2 * i + 1;
                const right = 2 * i + 2;
                
                if (left < heap.length && heap[left][0] < heap[smallest][0]) {
                    smallest = left;
                }
                if (right < heap.length && heap[right][0] < heap[smallest][0]) {
                    smallest = right;
                }
                
                if (smallest === i) break;
                
                [heap[i], heap[smallest]] = [heap[smallest], heap[i]];
                i = smallest;
            }
        }
        
        return top;
    }
    
    // Process buildings left to right
    for (let i = 0; i < n; i++) {
        // Resolve pending queries where current height satisfies condition
        while (heap.length > 0 && heap[0][0] < heights[i]) {
            const [, idx] = heapPop();
            ans[idx] = i;
        }
        
        // Add new queries that become active at this position
        for (const [reqHeight, idx] of queriesByB[i]) {
            heapPush([reqHeight, idx]);
        }
    }
    
    return ans;
};

```

Query 1: [0,3] → a=0,b=3
  heights[0]=6, heights[3]=5
  6 >= 5 → Case 3: pending at b=3, requiredHeight=6
  queriesByB[3] = [[6, 1]]

Query 2: [2,4] → a=2,b=4

```

### Step 2: Process Buildings Left to Right

```
i=0: heights[0]=6
  Heap empty, nothing to resolve
  queriesByB[0] empty, nothing to add
  heap = []

i=1: heights[1]=4
  Heap empty, nothing to resolve
  Add queriesByB[1]: push [6, 0]
  heap = [[6, 0]]

i=2: heights[2]=8
  Check heap top: [6, 0]
  6 < 8? Yes! Pop and resolve
  ans[0] = 2
  heap = []
  queriesByB[2] empty
  heap = []

i=3: heights[3]=5
  Heap empty, nothing to resolve
  Add queriesByB[3]: push [6, 1]
  heap = [[6, 1]]

i=4: heights[4]=2
  Check heap top: [6, 1]
  6 < 2? No, don't pop
  Add queriesByB[4]: push [8, 2], push [5, 3]
  heap = [[5, 3], [6, 1], [8, 2]] (after heapify, min=5)

i=5: heights[5]=7
  Check heap top: [5, 3]
  5 < 7? Yes! Pop and resolve
  ans[3] = 5
  heap = [[6, 1], [8, 2]]
  
  Check heap top: [6, 1]
  6 < 7? Yes! Pop and resolve
  ans[1] = 5
  heap = [[8, 2]]
  
  Check heap top: [8, 2]
  8 < 7? No, stop
  heap = [[8, 2]]
```

```
ans[0] = 2 (from i=2 processing)
ans[1] = 5 (from i=5 processing)
ans[2] = -1 (never resolved, stays default)
ans[3] = 5 (from i=5 processing)
ans[4] = 2 (immediate, same building)

# Key Insights

1. **Offline processing is essential:** By processing all queries together sorted by position, we avoid redundant searches
2. **Min-heap ensures leftmost answer:** Since we process indices in order and only resolve when the condition is met, the first resolution is guaranteed to be the leftmost
3. **Three distinct cases:** Immediate answers (same building, direct comparison) vs. deferred answers (complex height relationship)
4. **Amortized efficiency:** Each query is pushed and popped from the heap at most once, giving overall $O(q log q)$ for heap operations

---

# Edge Cases

| Case | Example | Explanation |
|------|---------|-------------|
| Same building | `[2,2]` | Immediate answer, no search needed |
| Direct comparison | `heights[a] < heights[b]` | Answer is `b` immediately |
| No valid meeting point | Heights don't increase enough | Answer remains `-1` |
| Meeting at last building | Valid `j` is `n-1` | Correctly found via heap resolution |
| Multiple queries same `b` | Multiple queries need same starting point | Handled independently in heap |

# Common Mistakes to Avoid

1. **Not handling a > b:**
   ```typescript
   // Wrong: assumes a <= b always
   if (heights[a] < heights[b]) { ... }
   
   // Correct: normalize first
   if (a > b) [a, b] = [b, a];
   ```

2. **Incorrect heap comparison for resolution:**
   ```typescript
   // Wrong: using <= instead of <
   while (heap[0][0] <= heights[i]) { ... }
   
   // Correct: strict inequality (need heights[j] > requiredHeight)
   while (heap[0][0] < heights[i]) { ... }
   ```

3. **Adding queries before checking current index:**
   ```typescript
   // Wrong: adding before resolving might cause incorrect early resolution
   queriesByB[i].forEach(q => heapPush(q));
   while (heap[0][0] < heights[i]) { ... }
   
   // Correct: resolve first, then add (queries become active from i+1)
   while (heap[0][0] < heights[i]) { ... }
   queriesByB[i].forEach(q => heapPush(q));
   ```

# Recommended Solution

This offline approach with min-heap is optimal for:
- $O((n+q) log q)$ time complexity
- Handles all edge cases correctly
- Efficient for large inputs (n, q up to 5×10⁴)
- Guarantees leftmost answer through ordered processing
- Production-ready implementation

> This is the standard and most efficient solution for this type of "leftmost satisfying condition" problem with multiple queries!
