# Intuition

This is a classic **Minimum Spanning Tree (MST)** problem where every pair of points has an edge with weight equal to their **Manhattan distance**. We need to connect all points with minimum total cost, ensuring exactly one path between any two points (i.e., a tree structure).

**Key insight:** Since the graph is **complete** (every point connects to every other point), we have $O(n²)$ possible edges. With `n ≤ 1000`, this means up to ~500,000 edges. **Prim's algorithm** with $O(n²)$ complexity (without a heap) is ideal here since it avoids the overhead of sorting all edges.

---

# Approach

## Prim's Algorithm (Dense Graph Optimization)

1. **Start with any point** (e.g., point 0) as part of the MST
2. **Maintain a `minDist` array:** tracks the minimum distance from each unvisited point to the current MST
3. **Repeat n-1 times:**
   - Find the unvisited point with the smallest `minDist` value
   - Add it to the MST, add its distance to the total cost
   - Update `minDist` for all other unvisited points based on the newly added point
4. **Return total cost**

This approach avoids using a priority queue since we're working with a dense graph - a simple $O(n)$ scan to find the minimum is efficient enough given the $O(n²)$ overall complexity is unavoidable anyway (due to the complete graph).

---

# Complexity

**Time Complexity:** $O(n²)$
- For each of the n-1 iterations, we scan all n points to find minimum and update distances
- Total: $O(n²)$

**Space Complexity:** $O(n)$
- `minDist` and `visited` arrays

For n = 1000, this gives 10⁶ operations - very efficient.

# Code

```typescript
function minCostConnectPoints(points: number[][]): number {
    const n = points.length;
    
    if (n <= 1) return 0;
    
    const visited: boolean[] = new Array(n).fill(false);
    const minDist: number[] = new Array(n).fill(Infinity);
    
    minDist[0] = 0;
    let totalCost = 0;
    
    for (let i = 0; i < n; i++) {
        // Find the unvisited point with minimum distance
        let u = -1;
        for (let v = 0; v < n; v++) {
            if (!visited[v] && (u === -1 || minDist[v] < minDist[u])) {
                u = v;
            }
        }
        
        // Add this point to MST
        visited[u] = true;
        totalCost += minDist[u];
        
        // Update distances for remaining unvisited points
        for (let v = 0; v < n; v++) {
            if (!visited[v]) {
                const dist = Math.abs(points[u][0] - points[v][0]) + 
                             Math.abs(points[u][1] - points[v][1]);
                if (dist < minDist[v]) {
                    minDist[v] = dist;
                }
            }
        }
    }
    
    return totalCost;
};

```

## Solution with Detailed Comments

```typescript
function minCostConnectPoints(points: number[][]): number {
    const n = points.length;
    
    // Edge case: single point needs no connections
    if (n <= 1) return 0;
    
    // Track which points are already in our MST
    const visited: boolean[] = new Array(n).fill(false);
    
    // Track minimum distance from each point to the current MST
    const minDist: number[] = new Array(n).fill(Infinity);
    
    // Start from point 0 (arbitrary starting point)
    minDist[0] = 0;
    let totalCost = 0;
    
    // Build MST by adding one point at a time
    for (let i = 0; i < n; i++) {
        // Step 1: Find the closest unvisited point to current MST
        let u = -1;
        for (let v = 0; v < n; v++) {
            if (!visited[v] && (u === -1 || minDist[v] < minDist[u])) {
                u = v;
            }
        }
        
        // Step 2: Add this point to the MST
        visited[u] = true;
        totalCost += minDist[u];
        
        // Step 3: Update minimum distances for all unvisited points
        // considering the newly added point u
        for (let v = 0; v < n; v++) {
            if (!visited[v]) {
                // Calculate Manhattan distance between u and v
                const dist = Math.abs(points[u][0] - points[v][0]) + 
                             Math.abs(points[u][1] - points[v][1]);
                
                // Update if this new edge is shorter than previous best
                if (dist < minDist[v]) {
                    minDist[v] = dist;
                }
            }
        }
    }
    
    return totalCost;
};

```

# Key Insights

1. **Dense graph optimization:** With $O(n²)$ edges in a complete graph, Prim's $O(n²)$ implementation (without heap) is optimal - using a heap would add unnecessary $O(log n)$ overhead
2. **Greedy approach works:** At each step, adding the minimum-weight edge to an unvisited vertex maintains the MST property
3. **No need to store all edges:** Unlike Kruskal's, we calculate distances on-the-fly, saving memory
4. **Manhattan distance calculation:** Simple formula `|x1-x2| + |y1-y2|` computed only when needed

| Duplicate distances | Multiple equal-weight paths | Any valid MST | Multiple optimal solutions possible |

# Common Mistakes to Avoid

1. **Using Kruskal's with full edge generation for large n:**
   ```typescript
   // Wrong: generates $O(n²)$ edges and sorts them - unnecessary overhead
   const edges = [];
   for (let i = 0; i < n; i++)
       for (let j = i+1; j < n; j++)
           edges.push([i, j, distance]);
   edges.sort(...);
   
   // Correct: Prim's avoids edge generation entirely
   ```

2. **Not initializing minDist correctly:**
   ```typescript
   // Wrong: starting all distances at 0
   const minDist = new Array(n).fill(0);
   
   // Correct: only starting point has distance 0
   const minDist = new Array(n).fill(Infinity);
   minDist[0] = 0;
   ```

3. **Forgetting to mark visited before updating distances:**
   ```typescript
   // Wrong: updating distances before marking visited
   // could cause incorrect self-comparison
   
   // Correct: mark visited first, then update others
   visited[u] = true;
   totalCost += minDist[u];
   // Then update remaining unvisited points
   ```

# Alternative: Kruskal's Algorithm (For Comparison)

```typescript
function minCostConnectPoints(points: number[][]): number {
    const n = points.length;
    const edges: number[][] = [];
    
    // Generate all edges
    for (let i = 0; i < n; i++) {
        for (let j = i + 1; j < n; j++) {
            const dist = Math.abs(points[i][0] - points[j][0]) + 
                         Math.abs(points[i][1] - points[j][1]);
            edges.push([dist, i, j]);
        }
    }
    
    edges.sort((a, b) => a[0] - b[0]);
    
    const parent = Array.from({length: n}, (_, i) => i);
    function find(x: number): number {
        if (parent[x] !== x) parent[x] = find(parent[x]);
        return parent[x];
    }
    
    let totalCost = 0;
    let edgesUsed = 0;
    
    for (const [dist, u, v] of edges) {
        const rootU = find(u), rootV = find(v);
        if (rootU !== rootV) {
            parent[rootU] = rootV;
            totalCost += dist;
            edgesUsed++;
            if (edgesUsed === n - 1) break;
        }
    }
    
    return totalCost;
};

```

**Comparison:** Kruskal's requires $O(n² log n)$ due to sorting, making Prim's the better choice for this dense graph problem.
