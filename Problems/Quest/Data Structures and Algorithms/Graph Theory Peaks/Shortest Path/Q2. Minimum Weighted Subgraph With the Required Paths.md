# Intuition

We need to find the **minimum total weight** to reach `dest` from both `src1` and `src2`. The key insight is that **paths can share edges** to minimize the total cost.

**Critical observation:** Instead of finding two separate paths, we should find a **meeting point** where paths from `src1` and `src2` converge, then continue together to `dest`.

```
src1 ────────→ meeting point ────────→ dest
                     ↑
src2 ────────────────┘

Total cost = dist[src1→meeting] + dist[src2→meeting] + dist[meeting→dest]
```

By trying every node as a potential meeting point and choosing the one with minimum total cost, we find the optimal solution.

---

# Approach

## High-Level Strategy

1. **Build two graphs:**
   - **Original graph:** For finding paths FROM `src1` and `src2`
   - **Reversed graph:** For finding paths TO `dest` (by reversing all edge directions)

2. **Run Dijkstra's algorithm 3 times:**
   - From `src1` in original graph → distances from `src1` to all nodes
   - From `src2` in original graph → distances from `src2` to all nodes
   - From `dest` in reversed graph → distances from all nodes to `dest`

3. **Find optimal meeting point:**
   - For each node `i`, calculate: `d1[i] + d2[i] + d3[i]`
   - Track the minimum sum
   - Return -1 if no valid path exists

## Why Reverse Graph?

Running Dijkstra from `dest` in the **reversed graph** is equivalent to finding shortest paths from **all nodes to `dest`** in the original graph. This is much more efficient than running Dijkstra from each node to `dest`.

```
Original: node → ... → dest
Reversed: dest → ... → node (same path, opposite direction)
```

## Optimized Binary Heap Implementation

The solution uses a **flat array binary heap** for maximum performance:

- **Flat storage:** `[dist₀, node₀, dist₁, node₁, ...]` (pairs stored consecutively)
- **Index calculation:** 
  - Left child: `2 * i + 2`
  - Right child: `2 * i + 4`
  - Parent: `((i / 2) | 0) & ~1` (ensures even index)
- **Operations:** O(log n) insert and extract-min

# Complexity

## Time Complexity: **$O((V + E) log V)$**

| Operation | Time | Count | Total |
|-----------|------|-------|-------|
| Build graphs | $O(E)$ | 1 | $O(E)$ |
| Dijkstra | $O((V+E) log V)$ | 3 | $O((V+E) log V)$ |
| Find minimum | $O(V)$ | 1 | $O(V)$ |
| **Overall** | - | - | **$O((V+E) log V)$** |

**Breakdown of Dijkstra:**
- Each node processed once: $O(V)$
- Each edge relaxed once: $O(E)$
- Heap operations: $O(log V)$ per operation
- Total: $O((V + E) log V)$

## Space Complexity: **$O(V + E)$**

| Component | Space |
|-----------|-------|
| Adjacency lists | $O(E)$ |
| Distance arrays | $O(V)$ |
| Binary heap | $O(V)$ |
| **Total** | **$O(V + E)$** |

# Code

```typescript
function minimumWeight(
    n: number,
    edges: number[][],
    src1: number,
    src2: number,
    dest: number
): number {
    const graph: number[][] = Array(n);
    const reverseGraph: number[][] = Array(n);

    for (let i = 0; i < n; i++) {
        graph[i] = [];
        reverseGraph[i] = [];
    }

    for (const edge of edges) {
        graph[edge[0]].push(edge[1], edge[2]);
        reverseGraph[edge[1]].push(edge[0], edge[2]);
    }

    function dijkstra(start: number, adj: number[][]): number[] {
        const dist = Array(n).fill(Infinity);
        dist[start] = 0;

        const heap: number[] = [];
        let size = 0;

        heap[size++] = 0;
        heap[size++] = start;

        while (size > 0) {
            const d = heap[0];
            const u = heap[1];

            size -= 2;
            if (size > 0) {
                heap[0] = heap[size];
                heap[1] = heap[size + 1];

                let i = 0;
                while (true) {
                    let smallest = i;
                    const left = 2 * i + 2;
                    const right = 2 * i + 4;

                    if (left < size && heap[left] < heap[smallest]) {
                        smallest = left;
                    }
                    if (right < size && heap[right] < heap[smallest]) {
                        smallest = right;
                    }

                    if (smallest === i) break;

                    let tmp = heap[i];
                    heap[i] = heap[smallest];
                    heap[smallest] = tmp;

                    tmp = heap[i + 1];
                    heap[i + 1] = heap[smallest + 1];
                    heap[smallest + 1] = tmp;

                    i = smallest;
                }
            }

            if (d > dist[u]) continue;

            const edges = adj[u];
            for (let i = 0; i < edges.length; i += 2) {
                const v = edges[i];
                const w = edges[i + 1];
                const newDist = d + w;

                if (newDist < dist[v]) {
                    dist[v] = newDist;

                    let pos = size;
                    heap[size++] = newDist;
                    heap[size++] = v;

                    while (pos > 0) {
                        const parent = ((pos / 2) | 0) & ~1;
                        if (heap[pos] >= heap[parent]) break;

                        let tmp = heap[pos];
                        heap[pos] = heap[parent];
                        heap[parent] = tmp;

                        tmp = heap[pos + 1];
                        heap[pos + 1] = heap[parent + 1];
                        heap[parent + 1] = tmp;

                        pos = parent;
                    }
                }
            }
        }

        return dist;
    }

    const d1 = dijkstra(src1, graph);
    const d2 = dijkstra(src2, graph);
    const d3 = dijkstra(dest, reverseGraph);

    let ans = Infinity;
    for (let i = 0; i < n; i++) {
        if (d1[i] < Infinity && d2[i] < Infinity && d3[i] < Infinity) {
            ans = Math.min(ans, d1[i] + d2[i] + d3[i]);
        }
    }

    return ans === Infinity ? -1 : ans;
}; 

```

## Example 2: `n = 3, edges = [[0,1,1],[2,1,1]], src1 = 0, src2 = 1, dest = 2`

### Graph Structure

**Original:**
```
0 → 1 (weight 1)
2 → 1 (weight 1)
```

**Reversed:**
```
1 → 0 (weight 1)
1 → 2 (weight 1)
```

### Dijkstra Results

**From src1 = 0:**
```
d1 = [0, 1, ∞]
(Node 2 is unreachable from 0)
```

**From src2 = 1:**
```
d2 = [∞, 0, ∞]
(Only node 1 is reachable from 1)
```

**From dest = 2 (reversed):**
```
d3 = [∞, 1, 0]
(Node 0 cannot reach 2 in reversed graph)
```

### Find Meeting Point

```
Node 0: 0 + ∞ + ∞ = ∞ (skip)
Node 1: 1 + 0 + 1 = 2 (but d2[1] path doesn't lead to dest)
Node 2: ∞ + ∞ + 0 = ∞ (skip)

All combinations have at least one ∞
```

**Output:** `-1`

**Why -1?** There's no path from `src2=1` to `dest=2` in the original graph.

## Why Reverse Graph Works

```
Original Graph (finding paths TO dest):
  Need: dist[node → dest] for all nodes
  Naive: Run Dijkstra from each node $(O(V × (V+E) log V))$

Reversed Graph (finding paths FROM dest):
  Run once: Dijkstra from dest in reversed graph
  Result: dist[dest → node] in reversed = dist[node → dest] in original
  Complexity: $O((V+E) log V)$ ✓
```

# Key Insights

1. **Meeting point optimization:** Paths can share edges from meeting point to destination
2. **Three Dijkstra runs:** More efficient than checking all path combinations
3. **Reverse graph trick:** Elegant way to find "all nodes to dest" in one pass
4. **Binary heap critical:** O(log n) operations vs O(n) for linear search
5. **Flat array heap:** Better cache locality and performance than object-based heap

---

# Why This Approach Works

**Correctness:**
- Any valid solution requires paths: `src1 → dest` and `src2 → dest`
- These paths may share edges (meeting point optimization)
- By trying all nodes as meeting points, we explore all possibilities
- Dijkstra guarantees shortest paths

**Optimality:**
- Dijkstra finds shortest paths from each source
- Trying all meeting points ensures we find the global minimum
- Total weight = sum of three shortest path segments

# Edge Cases

| Case | Example | Output | Explanation |
|------|---------|--------|-------------|
| No path from src1 | src1 isolated | -1 | d1[i] = ∞ for all i ≠ src1 |
| No path from src2 | src2 isolated | -1 | d2[i] = ∞ for all i ≠ src2 |
| No path to dest | dest unreachable | -1 | d3[i] = ∞ for all i |
| Direct paths optimal | No sharing needed | Sum of paths | Meeting at dest |
| Complete sharing | Same path works | Shared cost | Meeting early |
| Multiple edges | Parallel edges | Min weight | Dijkstra handles |

# Common Mistakes to Avoid

1. **Not using reversed graph:**
   ```typescript
   // Wrong: Run Dijkstra from each node to dest
   for (let i = 0; i < n; i++) {
       distToDest[i] = dijkstra(i, dest);
   }
   
   // Correct: One Dijkstra on reversed graph
   const distToDest = dijkstra(dest, reverseGraph);
   ```

2. **Forgetting to check all three distances:**
   ```typescript
   // Wrong: Might use unreachable node
   const total = d1[i] + d2[i] + d3[i];
   
   // Correct: Check for Infinity
   if (d1[i] < Infinity && d2[i] < Infinity && d3[i] < Infinity) {
       const total = d1[i] + d2[i] + d3[i];
   }
   ```

3. **Using inefficient priority queue:**
   ```typescript
   // Wrong: O(n²) with array.sort()
   pq.sort((a, b) => a[0] - b[0]);
   const min = pq.shift();
   
   // Correct: O(log n) with binary heap
   const min = heap.extractMin(); // O(log n)
   ```

4. **Not handling duplicate edges:**
   ```typescript
   // Dijkstra naturally handles duplicates
   // It will use the edge with minimum weight
   ```

**Why binary heap is critical:**
- Linear search: $O(V²)$ per Dijkstra = 10¹⁰ operations → TLE
- Binary heap: $O((V+E) log V)$ = ~10⁶ operations → AC ✓
