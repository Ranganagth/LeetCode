# Intuition

This problem requires implementing a dynamic graph that supports edge additions and shortest path queries. Since the graph can be modified after initialization, we need to compute shortest paths on-demand rather than pre-computing them.

**Key observations:**
1. Graph is directed and weighted
2. Edges can be added dynamically (no pre-computation possible)
3. Need efficient shortest path algorithm for each query
4. Small constraints (n ≤ 100, ≤ 100 queries) allow simpler implementations

**Best approach:** Use **Dijkstra's algorithm** for each shortest path query with a priority queue to efficiently find the minimum distance node.

---

# Approach

**Data Structure:**
- **Adjacency list:** Store graph as array of arrays
- Each `adj[u]` contains tuples `[neighbor, weight]`
- Simple and clean representation

**Operations:**

1. **Constructor:**
   - Initialize adjacency list for n nodes
   - Add all initial edges to adjacency list

2. **addEdge:**
   - Simply append the new edge to the adjacency list
   - $O(1)$ operation

3. **shortestPath (Dijkstra's Algorithm):**
   - Initialize distances to infinity, except source = 0
   - Use a min-heap (priority queue) to process nodes by distance
   - For each node, relax all outgoing edges
   - Early termination when target is reached
   - Return shortest distance or -1 if unreachable

**Priority Queue Implementation:**
- Use array with linear search for minimum
- Extract min by finding smallest element and swapping with last
- Simple but sufficient for small graphs (n ≤ 100)

**Why this works:**
- Dijkstra guarantees shortest path in weighted graphs
- Dynamic edge additions don't require recomputation
- Each query runs independently with current graph state

---

# Complexity

**Time Complexity:**

| Operation | Complexity | Explanation |
|-----------|-----------|-------------|
| `constructor` | $O(E)$ | Add E initial edges |
| `addEdge` | $O(1)$ | Append to adjacency list |
| `shortestPath` | $O(V² + E)$ | Dijkstra with linear search |

**Detailed shortestPath analysis:**
- Linear search for min: O(heap_size) per extraction
- Worst case heap size: $O(V + E)$ (multiple entries per node)
- Total extractions: $O(V)$
- Edge relaxations: $O(E)$
- Overall: $O(V × (V + E)) = O(V² + VE)$

**Space Complexity:**
- Adjacency list: $O(V + E)$
- Distance array: $O(V)$
- Heap: $O(V + E)$ worst case
- Total: $O(V + E)$

**Note:** For n ≤ 100, this is perfectly acceptable. A binary heap would be O((V+E) log V) but adds complexity.

# Code

```typescript
class Graph {
    private n: number;
    private adj: Array<Array<[number, number]>>;

    constructor(n: number, edges: number[][]) {
        this.n = n;
        // Initialize adjacency list for all nodes
        this.adj = Array.from({ length: n }, () => []);
        
        // Add all initial edges
        for (const [from, to, cost] of edges) {
            this.adj[from].push([to, cost]);
        }
    }

    addEdge(edge: number[]): void {
        const [from, to, cost] = edge;
        this.adj[from].push([to, cost]);
    }

    shortestPath(node1: number, node2: number): number {
        // Initialize distances to infinity
        const dist = new Array(this.n).fill(Infinity);
        dist[node1] = 0;

        // Priority queue: [distance, node]
        const heap: Array<[number, number]> = [[0, node1]];

        while (heap.length > 0) {
            // Find and extract minimum distance node
            let minIdx = 0;
            for (let i = 1; i < heap.length; i++) {
                if (heap[i][0] < heap[minIdx][0]) {
                    minIdx = i;
                }
            }
            
            const [d, u] = heap[minIdx];
            // Remove from heap by swapping with last element
            heap[minIdx] = heap[heap.length - 1];
            heap.pop();

            // Skip if we've already found a better path
            if (d > dist[u]) continue;

            // Early termination: reached target
            if (u === node2) return d;

            // Relax all outgoing edges
            for (const [v, w] of this.adj[u]) {
                const newDist = d + w;
                
                if (newDist < dist[v]) {
                    dist[v] = newDist;
                    heap.push([newDist, v]);
                }
            }
        }

        // Return distance or -1 if unreachable
        return dist[node2] === Infinity ? -1 : dist[node2];
    }
};

```

# Key Insights

1. **Simple priority queue:** Linear search is acceptable for small graphs (n ≤ 100)
2. **Early termination:** Stop as soon as target node is extracted from heap
3. **Distance check:** Skip processing if current distance is outdated
4. **Dynamic updates:** Each query runs independently with current graph state
5. **Tuple storage:** `[distance, node]` pairs make comparisons easy

# Edge Cases

| Case | Input | Output | Explanation |
|------|-------|--------|-------------|
| No path exists | `shortestPath(0, 3)` initially | -1 | Node 3 unreachable from 0 |
| Direct edge | `shortestPath(0, 2)` | 5 | Single edge path |
| After addEdge | `shortestPath(0, 3)` after add | 6 | New path becomes available |
| Source = target | `shortestPath(0, 0)` | 0 | Distance to self is 0 |
| Multiple paths | `shortestPath(3, 2)` | 6 | Chooses shortest among multiple |

# Common Mistakes to Avoid

1. **Not checking if distance improved:**
   ```typescript
   // Important: skip outdated entries
   if (d > dist[u]) continue;
   ```

2. **Missing early termination:**
   ```typescript
   // Optimization: stop when target found
   if (u === node2) return d;
   ```

3. **Wrong heap extraction:**
   ```typescript
   // Correct: swap with last, then pop
   heap[minIdx] = heap[heap.length - 1];
   heap.pop();
   
   // Wrong: just remove at index (shifts all elements)
   heap.splice(minIdx, 1);
   ```

4. **Not initializing adjacency list properly:**
   ```typescript
   // Correct: create empty array for each node
   this.adj = Array.from({ length: n }, () => []);
   
   // Wrong: all nodes share same array
   this.adj = Array(n).fill([]);
   ```
