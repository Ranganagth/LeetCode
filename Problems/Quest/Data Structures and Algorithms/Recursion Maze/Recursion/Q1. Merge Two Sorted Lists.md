# Intuition

We need to merge two sorted linked lists into one sorted list by **splicing** the existing nodes (not creating new nodes). Since both lists are already sorted, we can use a **two-pointer approach** to compare nodes and link them in order.

**Key insight:** Use a dummy node to simplify edge cases and maintain a pointer to build the merged list.

---

# Approach

1. **Create a dummy node** to serve as the starting point

2. **Use two pointers** to traverse both lists:
   - Compare current nodes from both lists
   - Link the smaller node to the result
   - Move the pointer of the list we took from

3. **Handle remaining nodes:**
   - When one list is exhausted, link the rest of the other list

4. **Return dummy.next** (the actual head of merged list)

---

# Complexity

- **Time complexity:** $O(n + m)$ where n and m are lengths of the two lists
- **Space complexity:** $O(1)$ - only using pointers, no new nodes created

---

# Code

## Solution 1: Iterative (Recommended)

```typescript
function mergeTwoLists(list1: ListNode | null, list2: ListNode | null): ListNode | null {
    // Create dummy node to simplify edge cases
    const dummy = new ListNode(0);
    let current = dummy;
    
    // Traverse both lists
    while (list1 !== null && list2 !== null) {
        if (list1.val <= list2.val) {
            // Link node from list1
            current.next = list1;
            list1 = list1.next;
        } else {
            // Link node from list2
            current.next = list2;
            list2 = list2.next;
        }
        current = current.next;
    }
    
    // Link remaining nodes (at most one list has remaining nodes)
    current.next = list1 !== null ? list1 : list2;
    
    return dummy.next;
};

```

## Solution 2: Recursive

```typescript
function mergeTwoLists(list1: ListNode | null, list2: ListNode | null): ListNode | null {
    // Base cases
    if (list1 === null) return list2;
    if (list2 === null) return list1;
    
    // Recursive case: choose smaller node and recurse
    if (list1.val <= list2.val) {
        list1.next = mergeTwoLists(list1.next, list2);
        return list1;
    } else {
        list2.next = mergeTwoLists(list1, list2.next);
        return list2;
    }
};

```

## Solution 3: Iterative with Detailed Comments

```typescript
function mergeTwoLists(list1: ListNode | null, list2: ListNode | null): ListNode | null {
    // Edge cases: if either list is empty
    if (list1 === null) return list2;
    if (list2 === null) return list1;
    
    // Dummy node to avoid special handling of head
    const dummy = new ListNode(0);
    let tail = dummy; // Pointer to build the merged list
    
    // Pointers for traversing input lists
    let p1 = list1;
    let p2 = list2;
    
    // Merge while both lists have nodes
    while (p1 !== null && p2 !== null) {
        if (p1.val <= p2.val) {
            // Take node from list1
            tail.next = p1;
            p1 = p1.next;
        } else {
            // Take node from list2
            tail.next = p2;
            p2 = p2.next;
        }
        // Move tail pointer forward
        tail = tail.next;
    }
    
    // Attach remaining nodes (only one list can have remaining nodes)
    if (p1 !== null) {
        tail.next = p1;
    } else {
        tail.next = p2;
    }
    
    // Return the head of merged list (skip dummy)
    return dummy.next;
};

```

## Solution 4: In-place Without Dummy

```typescript
function mergeTwoLists(list1: ListNode | null, list2: ListNode | null): ListNode | null {
    if (list1 === null) return list2;
    if (list2 === null) return list1;
    
    // Determine head of merged list
    let head: ListNode;
    if (list1.val <= list2.val) {
        head = list1;
        list1 = list1.next;
    } else {
        head = list2;
        list2 = list2.next;
    }
    
    let current = head;
    
    // Merge remaining nodes
    while (list1 !== null && list2 !== null) {
        if (list1.val <= list2.val) {
            current.next = list1;
            list1 = list1.next;
        } else {
            current.next = list2;
            list2 = list2.next;
        }
        current = current.next;
    }
    
    // Attach remaining
    current.next = list1 !== null ? list1 : list2;
    
    return head;
};

```

## Example 1: `list1 = [1,2,4], list2 = [1,3,4]`

```
Initial state:
list1: 1 → 2 → 4 → null
list2: 1 → 3 → 4 → null
dummy: 0 → null
current: dummy

Step 1: Compare 1 and 1
  1 <= 1, take from list1
  dummy: 0 → 1
  list1: 2 → 4 → null
  current: 1

Step 2: Compare 2 and 1
  2 > 1, take from list2
  dummy: 0 → 1 → 1
  list2: 3 → 4 → null
  current: 1 (second one)

Step 3: Compare 2 and 3
  2 <= 3, take from list1
  dummy: 0 → 1 → 1 → 2
  list1: 4 → null
  current: 2

Step 4: Compare 4 and 3
  4 > 3, take from list2
  dummy: 0 → 1 → 1 → 2 → 3
  list2: 4 → null
  current: 3

Step 5: Compare 4 and 4
  4 <= 4, take from list1
  dummy: 0 → 1 → 1 → 2 → 3 → 4
  list1: null
  current: 4

Step 6: list1 is null, attach remaining list2
  dummy: 0 → 1 → 1 → 2 → 3 → 4 → 4 → null

Return dummy.next: 1 → 1 → 2 → 3 → 4 → 4
```

**Output:** `[1,1,2,3,4,4]`

# Key Insights

- **Dummy node trick:** Simplifies handling of the head node
- **Two pointers:** Compare and advance one at a time
- **No new nodes:** Reuse existing nodes (splicing)
- **Remaining nodes:** One simple assignment at the end
- **Sorted property:** Maintained throughout the merge

# Edge Cases

| Case | list1 | list2 | Output | Notes |
|------|-------|-------|--------|-------|
| Both empty | [] | [] | [] | Return null |
| One empty | [] | [1] | [1] | Return non-empty |
| Same values | [1,1] | [1,1] | [1,1,1,1] | All equal |
| No overlap | [1,2] | [3,4] | [1,2,3,4] | Disjoint ranges |
| One longer | [1] | [2,3,4] | [1,2,3,4] | Different lengths |

# Common Mistakes to Avoid

1. **Creating new nodes:**
   ```typescript
   // Wrong: creating new nodes
   current.next = new ListNode(list1.val);
   
   // Correct: reusing existing nodes
   current.next = list1;
   ```

2. **Not handling null lists:**
   ```typescript
   // Wrong: will crash if list is null
   while (list1 && list2) {
       if (list1.val <= list2.val) // OK
   }
   // Missing: what if one is null at start?
   
   // Correct: check at beginning
   if (list1 === null) return list2;
   if (list2 === null) return list1;
   ```

3. **Forgetting to move current pointer:**
   ```typescript
   // Wrong: current never moves
   current.next = list1;
   list1 = list1.next;
   // Missing: current = current.next;
   
   // Correct: move current
   current = current.next;
   ```

4. **Not attaching remaining nodes:**
   ```typescript
   // Wrong: missing remaining nodes
   while (list1 && list2) { ... }
   return dummy.next;
   
   // Correct: attach remaining
   current.next = list1 !== null ? list1 : list2;
   ```

# Performance Analysis

For lists of length n and m:

| Approach | Time | Space | Notes |
|----------|------|-------|-------|
| Iterative | $O(n + m)$ | $O(1)$ | Optimal |
| Recursive | $O(n + m)$ | $O(n + m)$ | Call stack |
| With dummy | $O(n + m)$ | $O(1)$ | Cleanest |
| Without dummy | $O(n + m)$ | $O(1)$ | More complex |

---

# When to Use Each Solution

**Solution 1 (Iterative with Dummy):**
- Best for interviews
- Clean and simple
- $O(1)$ space
- Easy to understand

**Solution 2 (Recursive):**
- Elegant and concise
- Good for small lists
- O(n) space due to call stack
- Risk of stack overflow

**Solution 3 (Detailed):**
- Good for learning
- Well-commented
- Shows all steps

**Solution 4 (Without Dummy):**
- Saves one node
- More complex logic
- Harder to maintain

---

# Recommended Solution

**Use Solution 1 (Iterative with Dummy)** for:
- $O(n + m)$ time complexity
- $O(1)$ space complexity
- Clean and readable
- Handles all edge cases elegantly
- Standard interview solution

> This is the optimal and most professional approach!
