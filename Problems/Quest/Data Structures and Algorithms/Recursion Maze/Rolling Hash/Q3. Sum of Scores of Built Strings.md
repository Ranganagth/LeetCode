# Intuition

We're building a string by **prepending** characters one at a time from right to left. Each intermediate string `si` is actually a **suffix** of the final string `sn`.

**Key insight:** 
- `s1` = last character of `s` (suffix starting at position `n-1`)
- `s2` = last 2 characters of `s` (suffix starting at position `n-2`)
- `si` = last `i` characters of `s` (suffix starting at position `n-i`)

We need to find the **longest common prefix (LCP)** between each suffix and the full string, then sum all these LCP lengths.

The **Z-algorithm** is perfect for this! It computes, for each position `i`, the length of the longest substring starting at `i` that matches a prefix of the string.

---

# Approach

1. **Use Z-algorithm** to build the Z-array where:
   - `Z[i]` = length of longest substring starting at position `i` that matches the prefix of `s`

2. **Z-array properties:**
   - `Z[0] = n` (the entire string matches itself)
   - `Z[i]` gives us the LCP between suffix starting at `i` and the full string

3. **Optimization with Z-box:**
   - Maintain a window `[left, right]` of the rightmost substring that matches a prefix
   - Reuse previously computed values when possible
   - Only extend when necessary

4. **Sum all Z values** to get the total score

---

# Complexity

- **Time complexity:** $O(n)$ - Z-algorithm processes each character at most twice
- **Space complexity:** $O(n)$ - Z-array storage

---

# Code

```typescript
function sumScores(s: string): number {
    const n = s.length;
    const z = new Array(n).fill(0);
    z[0] = n; // The full string matches itself
    
    let left = 0, right = 0;
    
    // Build Z-array using Z-algorithm
    for (let i = 1; i < n; i++) {
        // If i is within the current Z-box [left, right]
        if (i <= right) {
            // Reuse previously computed value
            z[i] = Math.min(right - i + 1, z[i - left]);
        }
        
        // Try to extend the match beyond what we know
        while (i + z[i] < n && s[z[i]] === s[i + z[i]]) {
            z[i]++;
        }
        
        // Update Z-box if we extended past the current right boundary
        if (i + z[i] - 1 > right) {
            left = i;
            right = i + z[i] - 1;
        }
    }
    
    // Sum all Z values
    return z.reduce((sum, val) => sum + val, 0);
};

```

## Example 1: `s = "babab"`

**Building process (prepending from right to left):**

```
s1 = "b" (s[4])
s2 = "ab" (s[3] + s[4])
s3 = "bab" (s[2] + s[3] + s[4])
s4 = "abab" (s[1] + s[2] + s[3] + s[4])
s5 = "babab" (s[0] + s[1] + s[2] + s[3] + s[4])
```

**Computing Z-array for "babab":**

```
Position 0: "babab"
  Full string matches itself
  z[0] = 5

Position 1: "abab" vs "babab"
  s[1]='a' vs s[0]='b' → no match
  z[1] = 0

Position 2: "bab" vs "babab"
  s[2]='b' vs s[0]='b'
  s[3]='a' vs s[1]='a'
  s[4]='b' vs s[2]='b'
  z[2] = 3

Position 3: "ab" vs "babab"
  s[3]='a' vs s[0]='b' → no match
  z[3] = 0

Position 4: "b" vs "babab"
  s[4]='b' vs s[0]='b'
  z[4] = 1

Z-array: [5, 0, 3, 0, 1]
```

**Mapping to scores:**

```
s5 (position 0): LCP = 5 → "babab"
s4 (position 1): LCP = 0 → ""
s3 (position 2): LCP = 3 → "bab"
s2 (position 3): LCP = 0 → ""
s1 (position 4): LCP = 1 → "b"

Sum = 5 + 0 + 3 + 0 + 1 = 9
```

**Output:** `9`

# Key Insights

- **Suffix to prefix mapping:** Each `si` is a suffix of `s`, and we need its LCP with `s`
- **Z-algorithm efficiency:** Computes all LCPs in $O(n)$ time using the Z-box optimization
- **Z-box reuse:** When inside a known matching region, we can reuse previous computations
- **Linear guarantee:** Each character is compared at most twice (once when extending, once when in Z-box)

---

# Why Z-Algorithm Works

**The Z-box optimization:**

1. **Maintain invariant:** `[left, right]` is the rightmost substring that matches a prefix
2. **Inside Z-box:** If `i ≤ right`, we know `s[i...right]` matches `s[i-left...right-left]`
3. **Reuse knowledge:** `z[i-left]` tells us how much matches at the mirror position
4. **Extend carefully:** We can only guarantee matches up to `right`, then must check explicitly

**Example:**
```
String: a b a b a b
Z-box: [2, 5] after processing position 2

At i=4 (inside Z-box):
  Mirror: i-left = 4-2 = 2
  z[2] = 4, but we can only guarantee up to right
  z[4] = min(right-i+1, z[2]) = min(2, 4) = 2
  Then try to extend beyond position 5
```

# Common Mistakes to Avoid

1. **Wrong Z-box update:**
   ```typescript
   // Wrong: not updating left
   if (i + z[i] - 1 > right) {
       right = i + z[i] - 1;
   }
   
   // Correct: update both left and right
   if (i + z[i] - 1 > right) {
       left = i;
       right = i + z[i] - 1;
   }
   ```

2. **Incorrect Z-box reuse:**
   ```typescript
   // Wrong: not capping at Z-box boundary
   if (i <= right) {
       z[i] = z[i - left];
   }
   
   // Correct: cap at remaining Z-box length
   if (i <= right) {
       z[i] = Math.min(right - i + 1, z[i - left]);
   }
   ```

3. **Forgetting z[0]:**
   ```typescript
   // Wrong: not initializing z[0]
   const z = new Array(n).fill(0);
   
   // Correct: z[0] is always n
   z[0] = n;
   ```
