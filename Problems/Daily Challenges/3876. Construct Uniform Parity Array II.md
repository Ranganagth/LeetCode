# Intuition

The key insight is that **parity flips only when subtracting an odd number**:

```text
parity(a - b) = parity(a) XOR parity(b)
```

Subtracting an even number keeps parity the same; subtracting an odd number flips it. Combined with the new constraint `nums1[i] - nums1[j] >= 1` (meaning `nums1[j] < nums1[i]`), this tells us:

> To flip an even value to odd (or vice versa), you need a **smaller** number of the *opposite* parity present in the array — specifically, you always need a **smaller odd number** to cause a flip (since subtracting odd is what flips parity).

This lets us reduce the problem to a simple **min-value check** instead of brute-force searching.

---

# Approach

## Step 1: Handle trivial cases

- If **all values are already odd** → return `true`.
- If **all values are already even** → return `true`.

## Step 2: Analyze "target all even" (mixed array)

To make everything even, every odd value would need to flip using a smaller odd number. But the **smallest odd value in the array has no smaller odd number available**, so it can never flip. Therefore:

> **Target "all even" is only achievable if there were no odd numbers to begin with** (already handled in Step 1).

So in a mixed array, target "all even" is always impossible.

## Step 3: Analyze "target all odd" (mixed array)

- Odd values already satisfy the target (keep as-is).
- Even values need to flip using some **smaller odd number**.

Let `minOdd` = the smallest odd value in the array.

- Any even value **greater than** `minOdd` can flip successfully (subtract `minOdd` from it).
- Any even value **less than** `minOdd` cannot flip (no smaller odd number exists).

So: **Target "all odd" works if and only if every even value in the array is greater than `minOdd`.**

## Step 4: Conclusion

- If array is already uniform → `true`.
- Otherwise, check if all even values exceed the minimum odd value → if yes, `true`; otherwise `false`.

---

# Complexity

- **Time complexity:** 
$$O(n)$$
Single pass to compute counts, minimum odd value, and validate all even values.

- **Space complexity:**
$$O(1)$$
Only a few scalar variables are used.

# Code

```typescript
function uniformArray(nums1: number[]): boolean {
    const n = nums1.length;

    let oddCount = 0;
    let minOdd = Infinity;

    for (const num of nums1) {
        if (num % 2 !== 0) {
            oddCount++;
            if (num < minOdd) {
                minOdd = num;
            }
        }
    }

    // Case 1: All already odd.
    if (oddCount === n) {
        return true;
    }

    // Case 2: All already even.
    if (oddCount === 0) {
        return true;
    }

    // Case 3: Mixed — check if target "all odd" is achievable.
    // Every even value must be greater than the smallest odd value.
    for (const num of nums1) {
        if (num % 2 === 0 && num < minOdd) {
            return false;
        }
    }

    return true;
};

```

# Example Walkthrough

## Example 1

```text
nums1 = [1, 4, 7]
```

- Odd values: `1, 7` → `minOdd = 1`
- Even values: `4`
- Check: `4 > 1`

All even values exceed `minOdd`, so target "all odd" works:
```text
nums2[0] = 1 (keep)
nums2[1] = 4 - 1 = 3 (odd)
nums2[2] = 7 (keep)
```

Output: `true`

## Example 2

```text
nums1 = [2, 3]
```

- Odd values: `3` → `minOdd = 3`
- Even values: `2`
- Check: `2 > 3`? **No**

The value `2` has no smaller odd number available to flip it to odd, and target "all even" is impossible since `3` is odd with no smaller odd to flip.

Output: `false`

## Example 3

```text
nums1 = [4, 6]
```

- `oddCount = 0` → all already even.

Output: `true`
