# Intuition

We need to find all missing integers between the minimum and maximum values in the array. Since the smallest and largest values are guaranteed to be present, we just need to identify which numbers in that range are missing.

**Key insight:** Create a set of existing numbers for $O(1)$ lookup, then iterate through the range `[min, max]` and collect missing numbers.

---

# Approach

1. **Find min and max** values in the array

2. **Create a set** of all numbers in `nums` for fast lookup

3. **Iterate through range** `[min, max]`:
   - If a number is not in the set, it's missing
   - Add it to the result

4. **Return the result** (already sorted since we iterate in order)

---

# Complexity

- **Time complexity:** $O(n + k)$ where n is array length, k is the range size (max - min)
- **Space complexity:** $O(n)$ for the set

---

# Code

```typescript
function findMissingElements(nums: number[]): number[] {
    // Find min and max
    const min = Math.min(...nums);
    const max = Math.max(...nums);
    
    // Create set for $O(1)$ lookup
    const numSet = new Set(nums);
    
    // Find missing numbers in range [min, max]
    const missing: number[] = [];
    for (let i = min; i <= max; i++) {
        if (!numSet.has(i)) {
            missing.push(i);
        }
    }
    
    return missing;
};

```

# Alternative Solutions

## Solution 2: Without Set (Using Sorting)

```typescript
function findMissingElements(nums: number[]): number[] {
    // Sort the array
    nums.sort((a, b) => a - b);
    
    const missing: number[] = [];
    
    // Check for gaps between consecutive numbers
    for (let i = 0; i < nums.length - 1; i++) {
        const current = nums[i];
        const next = nums[i + 1];
        
        // Add all missing numbers between current and next
        for (let j = current + 1; j < next; j++) {
            missing.push(j);
        }
    }
    
    return missing;
};

```

## Solution 3: Using Array as Hash

```typescript
function findMissingElements(nums: number[]): number[] {
    const min = Math.min(...nums);
    const max = Math.max(...nums);
    
    // Create boolean array for range
    const present = new Array(max - min + 1).fill(false);
    
    // Mark present numbers
    for (const num of nums) {
        present[num - min] = true;
    }
    
    // Collect missing numbers
    const missing: number[] = [];
    for (let i = 0; i < present.length; i++) {
        if (!present[i]) {
            missing.push(min + i);
        }
    }
    
    return missing;
};

```

## Solution 4: One-liner Approach

```typescript
function findMissingElements(nums: number[]): number[] {
    const min = Math.min(...nums);
    const max = Math.max(...nums);
    const numSet = new Set(nums);
    
    return Array.from(
        { length: max - min + 1 }, 
        (_, i) => min + i
    ).filter(num => !numSet.has(num));
};

```

# Key Insights

- **Set for fast lookup:** $O(1)$ membership check
- **Already sorted:** Iterating through range gives sorted result
- **Simple logic:** Just check each number in range
- **No sorting needed:** Using set avoids sorting overhead

# Common Mistakes to Avoid

1. **Not using set for lookup:**
   ```typescript
   // Wrong: O(n) lookup for each number
   for (let i = min; i <= max; i++) {
       if (!nums.includes(i)) {
           missing.push(i);
       }
   }
   
   // Correct: O(1) lookup with set
   const numSet = new Set(nums);
   if (!numSet.has(i)) {
       missing.push(i);
   }
   ```

2. **Sorting when not needed:**
   ```typescript
   // Wrong: unnecessary sorting
   nums.sort((a, b) => a - b);
   const min = nums[0];
   const max = nums[nums.length - 1];
   
   // Correct: use Math.min/max
   const min = Math.min(...nums);
   const max = Math.max(...nums);
   ```

3. **Wrong range boundaries:**
   ```typescript
   // Wrong: exclusive max
   for (let i = min; i < max; i++)
   
   // Correct: inclusive max
   for (let i = min; i <= max; i++)
   ```

| Approach | Time | Space | Notes |
|----------|------|-------|-------|
| Set-based | $O(n + k)$ | $O(n)$ | Optimal |
| Sorting | $O(n log n + k)$ | $O(1)$ | Slower |
| Array hash | $O(n + k)$ | $O(k)$ | More space |
| Includes | $O(n × k)$ | $O(1)$ | Too slow |

---

# When to Use Each Solution

**Solution 1 (Set-based):**
- Best for most cases
- Fast $O(1)$ lookup
- Clean and readable

**Solution 2 (Sorting):**
- When space is critical
- When input can be modified
- Slower due to sorting

**Solution 3 (Array hash):**
- When range is small
- Slightly faster than set
- More space for large ranges

**Solution 4 (One-liner):**
- Concise code
- Functional style
- Less readable

---

# Recommended Solution

**Use Solution 1 (Set-based)** for:
- $O(n + k)$ time complexity
- $O(n)$ space complexity
- Clean and efficient
- Easy to understand
- Best for interviews

> This is the optimal and most straightforward approach!
