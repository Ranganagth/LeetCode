# Intuition

The allowed operations can only change the array into a **cyclic rotation** of either:

- Increasing order: `[0, 1, 2, ..., n - 1]`
- Decreasing order: `[n - 1, ..., 2, 1, 0]`

Why?

- A **left rotation** preserves the circular order of elements.
- A **reverse** flips that circular order.

Therefore, sorting is possible only if `nums` is a cyclic version of increasing order or decreasing order.

We locate the position `p` where `0` occurs, then validate whether the array follows either pattern.

---

# Approach

Let `p` be the index where `nums[p] === 0`.

## 1. Check cyclic increasing order

For increasing cyclic order, moving forward from `0` must give:

```text
0, 1, 2, 3, ...
```

So at index `i`, the expected value is:

```text
(i - p + n) % n
```

If valid:

- Rotate left `p` times directly to sort it.
- Or simulate rotating right `n - p` times using:

```text
reverse -> rotate left (n - p) times -> reverse
```

This costs `n - p + 2`.

So the best cost is:

```text
min(p, n - p + 2)
```

## 2. Check cyclic decreasing order

For decreasing cyclic order, moving forward from `0` must give:

```text
0, n - 1, n - 2, ...
```

So at index `i`, the expected value is:

```text
(p - i + n) % n
```

There are two useful ways to sort:

- Reverse immediately, then rotate left as needed: cost `n - p`.
- Rotate left first, then reverse: cost `p + 2`.

So the best cost is:

```text
min(n - p, p + 2)
```

## 3. If neither pattern matches

It is impossible to sort the array with only the given operations, so return `-1`.

---

# Complexity

- **Time Complexity:**
$$O(n)$$
We find `0` and validate at most two circular patterns.

- **Space Complexity:**
$$O(1)$$
Only a few variables are used.

---

# Code

```typescript
function minOperations(nums: number[]): number {
    const n = nums.length;

    if (n === 1) {
        return 0;
    }

    const zeroIndex = nums.indexOf(0);

    let isIncreasingRotation = true;
    let isDecreasingRotation = true;

    for (let i = 0; i < n; i++) {
        const expectedIncreasing = (i - zeroIndex + n) % n;
        const expectedDecreasing = (zeroIndex - i + n) % n;

        if (nums[i] !== expectedIncreasing) {
            isIncreasingRotation = false;
        }

        if (nums[i] !== expectedDecreasing) {
            isDecreasingRotation = false;
        }
    }

    let answer = Infinity;

    // nums is a cyclic rotation of [0, 1, 2, ..., n - 1]
    if (isIncreasingRotation) {
        answer = Math.min(answer, zeroIndex, n - zeroIndex + 2);
    }

    // nums is a cyclic rotation of [0, n - 1, n - 2, ..., 1]
    if (isDecreasingRotation) {
        answer = Math.min(answer, n - zeroIndex, zeroIndex + 2);
    }

    return answer === Infinity ? -1 : answer;
};

```

# Example Walkthrough

## Example 1

```text
nums = [0, 2, 1]
```

- `n = 3`
- `0` is at index `p = 0`.

Check increasing rotation:

```text
Expected: [0, 1, 2]
Actual: [0, 2, 1]
```

Not increasing.

Check decreasing rotation:

```text
Expected from 0: [0, 2, 1]
Actual: [0, 2, 1]
```

It is decreasing cyclic order.

Possible costs:

```text
Reverse immediately:
[0, 2, 1] -> [1, 2, 0]
Then rotate left twice -> [0, 1, 2]
Cost = 3

Rotate left once, then reverse:
[0, 2, 1] -> [2, 1, 0] -> [0, 1, 2]
Cost = 2
```

```text
min(n - p, p + 2)
= min(3 - 0, 0 + 2)
= 2
```

Output: `2`

---

## Example 2

```text
nums = [1, 0, 2]
```

- `n = 3`
- `0` is at index `p = 1`.

Increasing check fails.

Decreasing cyclic order from `0` is:

```text
[1, 0, 2]
```

Valid.

Possible costs:

```text
Reverse:
[1, 0, 2] -> [2, 0, 1]

Rotate left once:
[2, 0, 1] -> [0, 1, 2]
```

Cost:

```text
n - p = 3 - 1 = 2
```

Output: `2`

---

## Example 3

```text
nums = [2, 0, 1, 3]
```

- `0` is at index `1`.

Starting from `0`:

```text
Actual circular order: 0, 1, 3, 2
```

This is neither:

```text
Increasing: 0, 1, 2, 3
Decreasing: 0, 3, 2, 1
```

Sorting is impossible with only rotations and reversals.

Output: `-1`
