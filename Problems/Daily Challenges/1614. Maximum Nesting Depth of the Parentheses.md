# Intuition

Since `s` is guaranteed to be a **Valid Parentheses String (VPS)**, every `(` has a matching `)`. The "nesting depth" at any point in the string is simply *how many unmatched `(` characters have been opened but not yet closed* at that point.

So if we just walk through the string left to right, keeping a running counter that goes **up** on `(` and **down** on `)`, the counter's value at any moment tells us exactly how deeply nested we currently are. The answer is just the **highest value this counter ever reaches**.

Digits and operators (`+`, `-`, `*`, `/`) don't affect nesting at all — they can be completely ignored.

---

# Approach

1. Initialize `depth = 0` (current nesting level) and `maxDepth = 0` (highest nesting level seen so far).
2. Iterate through each character of `s`:
   - If it's `(` → increment `depth`, then update `maxDepth = max(maxDepth, depth)`.
   - If it's `)` → decrement `depth`.
   - Otherwise (digit or operator) → do nothing.
3. After scanning the whole string, `maxDepth` holds the answer.

This is a classic **single-pass counter / stack-simulation** technique — instead of using an actual stack (which would work too, since VPS guarantees balance), we only need the *count* of open brackets, not their identity, so a simple integer counter suffices.

**Complexity:**
- ⏱️ Time: `O(n)` — one pass through the string.
- 📊 Space: `O(1)` — only two integer variables, no extra data structure needed.

---

# Code

```typescript
function maxDepth(s: string): number {
    let depth = 0;
    let maxD = 0;

    for (const ch of s) {
        if (ch === '(') {
            depth++;
            maxD = Math.max(maxD, depth);
        } else if (ch === ')') {
            depth--;
        }
        // digits and operators (+, -, *, /) are ignored
    }

    return maxD;
};

```

# Example Walkthrough

## Example 1: `s = "(1+(2*3)+((8)/4))+1"`

Let's track `depth` and `maxD` character by character:

| Char | Action | depth | maxD |
|---|---|---|---|
| `(` | depth++ | 1 | 1 |
| `1` | ignore | 1 | 1 |
| `+` | ignore | 1 | 1 |
| `(` | depth++ | 2 | 2 |
| `2` | ignore | 2 | 2 |
| `*` | ignore | 2 | 2 |
| `3` | ignore | 2 | 2 |
| `)` | depth-- | 1 | 2 |
| `+` | ignore | 1 | 2 |
| `(` | depth++ | 2 | 2 |
| `(` | depth++ | **3** | **3** |
| `8` | ignore | 3 | 3 |
| `)` | depth-- | 2 | 3 |
| `/` | ignore | 2 | 3 |
| `4` | ignore | 2 | 3 |
| `)` | depth-- | 1 | 3 |
| `)` | depth-- | 0 | 3 |
| `+` | ignore | 0 | 3 |
| `1` | ignore | 0 | 3 |

Final `maxD = 3` — matches the expected output. Notice depth hits `3` exactly when we reach digit `8`, confirming the explanation given.

### Example 3: `s = "()(())((()()))"`

Quick trace focusing on depth changes:

```
( → depth=1, maxD=1
) → depth=0
( → depth=1, maxD=1
    ( → depth=2, maxD=2
    ) → depth=1
) → depth=0
( → depth=1, maxD=2
    ( → depth=2, maxD=2
        ( → depth=3, maxD=3 ← new max!
        ) → depth=2
        ( → depth=3, maxD=3
        ) → depth=2
    ) → depth=1
) → depth=0
```

Final `maxD = 3` — matches the expected output.

## Key Takeaway

Because the string is guaranteed valid (VPS), you never need to worry about mismatched brackets or going negative — the simple increment/decrement counter is sufficient, and there's no need for an actual `Stack<string>` data structure since we only care about the *count* of nesting, not reconstructing which bracket matches which.
