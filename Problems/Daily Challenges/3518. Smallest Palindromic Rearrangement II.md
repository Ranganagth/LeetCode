# Intuition

The given solution uses a **combinatorial approach** to directly compute the k-th palindromic permutation without generating all permutations. 

**Key insight:** Since a palindrome is determined by its first half, we only need to find the k-th permutation of the first half. We can use combinatorics to calculate how many permutations start with each character and skip directly to the k-th one.

---

# Approach

1. **Extract first half:** Only the first `floor(n/2)` characters determine the palindrome

2. **Count character frequencies** in the first half using a bucket array

3. **Combinatorial calculation:** For each position, calculate how many valid permutations exist if we place each character there

4. **Greedy selection:** At each position, try characters in alphabetical order:
   - Calculate how many permutations start with this character
   - If k falls within this range, use this character
   - Otherwise, skip these permutations and try the next character

5. **Build palindrome:** Construct left half + middle (if odd length) + reversed left half

---

# Complexity

- **Time complexity:** $O(n + 26 × n) = O(n)$ where n is string length
  - Counting frequencies: $O(n)$
  - Building result: $O(26 × n/2)$ for trying each character at each position

- **Space complexity:** $O(1)$ - fixed size bucket array (26 characters)

# Code Explanation

```typescript
// Helper: Calculate combinations C(n, m) with early termination if > k
const C = (n: number, m: number, k: number) => {
    let res = 1;
    m = Math.min(m, n - m); // Optimization: C(n,m) = C(n,n-m)

    for (let i = 1; i <= m; i++) {
        res = (res * (n - i + 1)) / i;
        if (res > k) {
            return k + 1; // Early termination: we only care if res > k
        }
    }
    return res;
};

function smallestPalindrome(s: string, k: number): string {
    const partition = Math.floor(s.length / 2);
    const bucket = new Int32Array(26); // Frequency of each character in first half

    // Count character frequencies in first half
    for (let i = 0; i < partition; i++) {
        bucket[s.charCodeAt(i) - 97] += 1;
    }

    // Calculate number of permutations with remaining characters
    const permutations = (rem: number) => {
        let ways = 1;
        for (let i = 0; i < 26; i++) {
            if (bucket[i] === 0) continue;

            // Multiply by C(rem, bucket[i]) - ways to place bucket[i] chars in rem positions
            ways *= C(rem, bucket[i], k);
            if (ways > k) break; // Early termination
            rem -= bucket[i];
        }
        return ways;
    };

    let left = "";
    let startIndex = 1; // Current permutation index (1-indexed)
    
    // Build left half character by character
    for (let pos = 0; pos < partition; pos++) {
        // Try each character in alphabetical order
        for (let i = 0; i < 26; i++) {
            if (bucket[i] === 0) continue;

            // Temporarily use this character
            bucket[i] -= 1;

            // Calculate how many permutations start with this character
            const ways = permutations(partition - pos - 1);
            
            // Check if k-th permutation uses this character at this position
            if (startIndex + ways > k) {
                // k-th permutation is in this range, use this character
                left += String.fromCharCode(i + 97);
                break;
            }

            // k-th permutation is not in this range, restore and try next character
            bucket[i] += 1;
            startIndex += ways;
        }
    }

    // If we couldn't build complete left half, k exceeds total permutations
    if (left.length < partition) {
        return "";
    }

    // Build complete palindrome
    const mid = s.length % 2 !== 0 ? s[partition] : "";
    const right = left.split("").reverse().join("");

    return left + mid + right;
};

```

# Key Insights

- **Combinatorial skip:** Instead of generating permutations, we calculate and skip ranges
- **Greedy character selection:** Always try characters in alphabetical order
- **Early termination:** Stop calculating combinations when they exceed k
- **Efficient:** O(n) time instead of O(k × n) for next permutation approach
- **Direct computation:** Jump directly to the k-th permutation

---

# Why This Works

**Mathematical foundation:**

For a multiset with character frequencies, the number of distinct permutations is:
```
n! / (c1! × c2! × ... × ck!)
```

Where n is total characters and ci is frequency of character i.

By fixing characters one by one and calculating remaining permutations, we can determine which character to place at each position to reach exactly the k-th permutation.
