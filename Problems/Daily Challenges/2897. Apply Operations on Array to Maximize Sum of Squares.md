# Intuition

The AND/OR operation described is a classic **bit redistribution** trick: it allows us to freely move individual **bits** between elements, as long as we preserve the **total count of set bits at each bit position** across the entire array. In other words, for each bit position, we can count how many numbers have that bit set, and then redistribute those bits however we like among the elements.

To **maximize** the sum of squares when choosing `k` elements, the optimal strategy is to **concentrate as many high bits as possible into as few elements as possible** — specifically, we want to form the `k` **largest possible numbers** by greedily assigning, for each bit position (from highest to lowest), that bit to as many of our `k` "target" elements as there are available copies of that bit (up to `k`), building up `k` maximized values **simultaneously** in parallel (like filling `k` buckets, one bit layer at a time, always keeping all buckets as balanced/maximal as possible from the top down).

This is because concentrating bits from many numbers into fewer numbers can only help, and distributing available bit-counts evenly across exactly `k` numbers at each bit level maximizes the eventual sum of squares (since squares benefit from larger individual values more than spreading bits thin).

---

# Approach

1. **Count bits**: For each of the 30-31 bit positions (since `nums[i] ≤ 10^9 < 2^30`), count how many numbers in `nums` have that bit set — call this `bitCount[b]`.
2. **Build k target numbers**: Initialize an array `result` of size `k`, all zeros. For each bit position `b` from highest (e.g., 30) down to `0`:
   - Let `c = min(bitCount[b], k)` — the number of our `k` target slots that can receive this bit.
   - Assign this bit to the **first `c`** target numbers: `result[i] |= (1 << b)` for `i` from `0` to `c-1`.
3. **Sum of squares**: Compute `sum(result[i]^2 for i in 0..k-1) % (10^9+7)`, using `BigInt` to avoid overflow since values and squares can be large.

This greedy bit-packing approach is a well-known technique for this type of "AND/OR bit redistribution" problem — it always produces the optimal maximum achievable `k` values.

---

# Complexity

- **Time complexity:**
$$O(n \cdot B + k \cdot B)$$
where `B ≈ 31` is the number of bit positions. This simplifies to `O((n+k) \cdot B)`, effectively linear in input size.

- **Space complexity:** 
$$O(k + B)$$
For storing the `result` array and bit counts.

# Code

```typescript
function maxSum(nums: number[], k: number): number {
    const MOD = 1_000_000_007n;
    const BITS = 31;

    const bitCount = new Array<number>(BITS).fill(0);

    for (const num of nums) {
        for (let b = 0; b < BITS; b++) {
            if ((num >> b) & 1) {
                bitCount[b]++;
            }
        }
    }

    const result = new Array<number>(k).fill(0);

    for (let b = BITS - 1; b >= 0; b--) {
        const c = Math.min(bitCount[b], k);
        for (let i = 0; i < c; i++) {
            result[i] |= (1 << b);
        }
    }

    let sum = 0n;
    for (let i = 0; i < k; i++) {
        const v = BigInt(result[i]);
        sum = (sum + v * v) % MOD;
    }

    return Number(sum);
};

```

# Example Walkthrough

## Example 1

```text
nums = [2,6,5,8], k = 2
```

Binary representations:
- `2 = 00010`
- `6 = 00110`
- `5 = 00101`
- `8 = 01000`

Bit counts (bit 0 = LSB):
- bit 0: `2→0,6→0,5→1,8→0` → count=1
- bit 1: `2→1,6→1,5→0,8→0` → count=2
- bit 2: `2→0,6→1,5→1,8→0` → count=2
- bit 3: `2→0,6→0,5→0,8→1` → count=1

Build `k=2` target numbers, bit by bit from highest (bit 3) down:
- bit 3 (count=1): c=min(1,2)=1 → result[0] |= 8 → result=[8,0]
- bit 2 (count=2): c=min(2,2)=2 → result[0]|=4, result[1]|=4 → result=[12,4]
- bit 1 (count=2): c=2 → result[0]|=2, result[1]|=2 → result=[14,6]
- bit 0 (count=1): c=1 → result[0]|=1 → result=[15,6]

Final: `result = [15, 6]`

```text
sum = 15² + 6² = 225 + 36 = 261
```

Output: `261`

## Example 2

```text
nums = [4,5,4,7], k = 3
```

Binary:
- `4=100, 5=101, 4=100, 7=111`

Bit counts:
- bit0: `0,1,0,1` → 2
- bit1: `0,0,0,1` → 1
- bit2: `1,1,1,1` → 4

Build `k=3` targets:
- bit2 (count=4): c=min(4,3)=3 → result=[4,4,4]
- bit1 (count=1): c=1 → result[0]|=2 → result=[6,4,4]
- bit0 (count=2): c=2 → result[0]|=1, result[1]|=1 → result=[7,5,4]

Final: `result=[7,5,4]`
