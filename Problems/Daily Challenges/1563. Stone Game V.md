# Intuition

This is a classic **interval dynamic programming** problem. At each round, Alice can choose any split point to divide the row into two parts, and Bob removes the larger sum (or Alice's choice if equal). We need to find the optimal strategy that **maximizes Alice's total score**.

**Key insight:** For any subarray `[i, j]`, Alice's maximum achievable score depends only on that subarray, not on how we got there. This makes it perfect for **interval DP**.

**State definition:** `dp[i][j]` = maximum score Alice can obtain from stones in range `[i, j]`

---

# Approach

## Recurrence Relation

For each subarray `[i, j]`, try every possible split point `k` (where `i <= k < j`):
- **Left part:** `[i, k]` with sum `leftSum`
- **Right part:** `[k+1, j]` with sum `rightSum`

**Three cases:**
1. If `leftSum < rightSum`: Right row is thrown away, Alice gets `leftSum + dp[i][k]`
2. If `leftSum > rightSum`: Left row is thrown away, Alice gets `rightSum + dp[k+1][j]`
3. If `leftSum == rightSum`: Alice chooses which to keep, gets `leftSum + max(dp[i][k], dp[k+1][j])`

**Final formula:**
```
dp[i][j] = max over all valid k of the above cases
```

**Base case:** `dp[i][i] = 0` (single stone, no more splits possible)

## Optimization: Prefix Sums

Use prefix sum array to calculate range sums in $O(1)$ time instead of $O(n)$.

## Implementation Strategy

Use **top-down memoization** (recursive with caching) for clarity, trying all split points for each subarray.

---

# Complexity

**Time Complexity:** $O(n³)$
- $O(n²)$ possible subarrays `[i, j]`
- $O(n)$ split points to try for each subarray
- Total: $O(n²) × O(n) = O(n³)$

**Space Complexity:** $O(n²)$
- Memoization table: $O(n²)$
- Prefix sum array: $O(n)$
- Recursion stack: $O(n)$

For n = 500: $O(n³) = 1.25 × 10⁸$ operations, which is acceptable within typical time limits.

# Code

## Solution 1: Bottom-Up DP (Iterative)

```typescript
function stoneGameV(stoneValue: number[]): number {
    const n = stoneValue.length;
    
    // Prefix sum for $O(1)$ range sum queries
    const prefixSum: number[] = new Array(n + 1).fill(0);
    for (let i = 0; i < n; i++) {
        prefixSum[i + 1] = prefixSum[i] + stoneValue[i];
    }
    
    const getSum = (left: number, right: number): number => {
        return prefixSum[right + 1] - prefixSum[left];
    };
    
    // dp[i][j] = maximum score for subarray [i, j]
    const dp: number[][] = Array.from({ length: n }, () => 
        new Array(n).fill(0)
    );
    
    // Fill dp table by increasing length of subarray
    for (let length = 2; length <= n; length++) {
        for (let i = 0; i <= n - length; i++) {
            const j = i + length - 1;
            
            let maxScore = 0;
            
            // Try all split points
            for (let k = i; k < j; k++) {
                const leftSum = getSum(i, k);
                const rightSum = getSum(k + 1, j);
                
                if (leftSum < rightSum) {
                    maxScore = Math.max(maxScore, leftSum + dp[i][k]);
                } else if (leftSum > rightSum) {
                    maxScore = Math.max(maxScore, rightSum + dp[k + 1][j]);
                } else {
                    maxScore = Math.max(
                        maxScore,
                        leftSum + Math.max(dp[i][k], dp[k + 1][j])
                    );
                }
            }
            
            dp[i][j] = maxScore;
        }
    }
    
    return dp[0][n - 1];
};

```

## Solution 2: With Detailed Comments

```typescript
function stoneGameV(stoneValue: number[]): number {
    const n = stoneValue.length;
    
    // Step 1: Build prefix sum array for O(1) range sum queries
    // prefixSum[i] = sum of stoneValue[0..i-1]
    const prefixSum: number[] = new Array(n + 1).fill(0);
    for (let i = 0; i < n; i++) {
        prefixSum[i + 1] = prefixSum[i] + stoneValue[i];
    }
    
    // Helper function to get sum of range [left, right] inclusive
    const getRangeSum = (left: number, right: number): number => {
        return prefixSum[right + 1] - prefixSum[left];
    };
    
    // Memoization cache
    const memo: Map<string, number> = new Map();
    
    // dp(i, j) returns maximum score Alice can get from stones[i..j]
    function dp(i: number, j: number): number {
        // Base case: only one stone left, game ends, no more score
        if (i >= j) {
            return 0;
        }
        
        // Check if already computed
        const cacheKey = `${i}_${j}`;
        if (memo.has(cacheKey)) {
            return memo.get(cacheKey)!;
        }
        
        let bestScore = 0;
        
        // Try every possible split point k
        // Left part: [i, k], Right part: [k+1, j]
        for (let k = i; k < j; k++) {
            const leftSum = getRangeSum(i, k);
            const rightSum = getRangeSum(k + 1, j);
            
            let currentScore: number;
            
            if (leftSum < rightSum) {
                // Bob throws away right (larger), Alice keeps left
                currentScore = leftSum + dp(i, k);
            } else if (leftSum > rightSum) {
                // Bob throws away left (larger), Alice keeps right
                currentScore = rightSum + dp(k + 1, j);
            } else {
                // Equal sums: Alice chooses which continuation is better
                currentScore = leftSum + Math.max(dp(i, k), dp(k + 1, j));
            }
            
            bestScore = Math.max(bestScore, currentScore);
        }
        
        // Cache and return result
        memo.set(cacheKey, bestScore);
        return bestScore;
    }
    
    return dp(0, n - 1);
};

```

## Solution 3: Optimized with Array-based Memoization

```typescript
function stoneGameV(stoneValue: number[]): number {
    const n = stoneValue.length;
    
    const prefixSum: number[] = new Array(n + 1).fill(0);
    for (let i = 0; i < n; i++) {
        prefixSum[i + 1] = prefixSum[i] + stoneValue[i];
    }
    
    const getSum = (left: number, right: number): number => {
        return prefixSum[right + 1] - prefixSum[left];
    };
    
    // Use 2D array for memoization (faster than Map)
    const memo: number[][] = Array.from({ length: n }, () => 
        new Array(n).fill(-1)
    );
    
    function dp(i: number, j: number): number {
        if (i >= j) return 0;
        if (memo[i][j] !== -1) return memo[i][j];
        
        let maxScore = 0;
        
        for (let k = i; k < j; k++) {
            const leftSum = getSum(i, k);
            const rightSum = getSum(k + 1, j);
            
            if (leftSum < rightSum) {
                maxScore = Math.max(maxScore, leftSum + dp(i, k));
            } else if (leftSum > rightSum) {
                maxScore = Math.max(maxScore, rightSum + dp(k + 1, j));
            } else {
                maxScore = Math.max(
                    maxScore,
                    leftSum + Math.max(dp(i, k), dp(k + 1, j))
                );
            }
        }
        
        memo[i][j] = maxScore;
        return maxScore;
    }
    
    return dp(0, n - 1);
};

```

# Visual Representation

## Interval DP Concept

```
dp[i][j] represents optimal score for subarray [i,j]

For subarray [0,5]:
  Try k=0,1,2,3,4 as split points
  
  [0,5]
   / \
[0,k] [k+1,5]
  
Recursively solve smaller subproblems first
Build up to larger intervals
```

## Memoization Table Growth

```
Length 1: dp[i][i] = 0 for all i (base case)

Length 2: dp[i][i+1] computed using length-1 results

Length 3: dp[i][i+2] computed using length-1 and length-2 results

...

Length n: dp[0][n-1] computed using all smaller results
```

---

# Key Insights

1. **Optimal substructure:** Best score for `[i,j]` depends only on best scores of sub-intervals
2. **Overlapping subproblems:** Same `[i,j]` ranges appear multiple times → memoization helps
3. **Prefix sums crucial:** $O(1)$ range sum queries instead of $O(n)$ recalculation
4. **Try all splits:** Must check every possible division point to find optimal
5. **Tie-breaking:** When sums are equal, Alice picks the better continuation

# Edge Cases

| Case | Input | Output | Explanation |
|------|-------|--------|-------------|
| Single stone | `[4]` | 0 | No splits possible |
| Two equal stones | `[5,5]` | 5 | Alice picks either |
| All equal | `[7,7,7,...]` | Varies | Symmetric splits |
| Strictly increasing | `[1,2,3,4,5]` | Varies | Greedy-like splits |
| Two stones | `[a,b]` | min(a,b) | Simple case |

# Common Mistakes to Avoid

1. **Not trying all split points:**
   ```typescript
   // Wrong: only trying middle split
   const k = Math.floor((i + j) / 2);
   
   // Correct: try all possible splits
   for (let k = i; k < j; k++) { ... }
   ```

2. **Forgetting prefix sums:**
   ```typescript
   // Wrong: O(n) sum calculation each time
   const leftSum = stoneValue.slice(i, k+1).reduce((a,b) => a+b);
   
   // Correct: O(1) with prefix sums
   const leftSum = prefixSum[k+1] - prefixSum[i];
   ```

3. **Incorrect base case:**
   ```typescript
   // Wrong: i > j instead of i >= j
   if (i > j) return 0;
   
   // Correct: single stone case included
   if (i >= j) return 0;
   ```

4. **Not handling equal sums properly:**
   ```typescript
   // Wrong: always keeping left when equal
   if (leftSum <= rightSum) {
       score = leftSum + dp(i, k);
   }
   
   // Correct: choose the better option
   if (leftSum === rightSum) {
       score = leftSum + Math.max(dp(i, k), dp(k+1, j));
   }
   ```
