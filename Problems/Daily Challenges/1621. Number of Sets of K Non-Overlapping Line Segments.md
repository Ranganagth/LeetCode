# Intuition

At first glance, this problem looks like it needs a full dynamic programming table tracking positions and segment counts. However, there's an elegant **combinatorial bijection** hiding underneath: since segments are allowed to **share endpoints** (touch but not cross), selecting `k` non-overlapping segments over `n` points is equivalent to choosing `2k` "cut positions" (with repetition allowed at endpoints) from a set that's been cleverly resized to account for that flexibility.

This transforms the entire problem into a single **binomial coefficient** calculation:

```text
answer = C(n + k - 1, 2k) mod (10^9 + 7)
```

We can verify this against the examples:
- `n=4, k=2` → `C(5, 4) = 5`
- `n=3, k=1` → `C(3, 2) = 3`

---

# Approach

## Why this formula works (intuition sketch)

Each of the `k` segments has a left endpoint and a right endpoint chosen from `{0, ..., n-1}`, with the constraint that segments don't overlap (they can only touch at shared endpoints) and each segment spans **at least 1 unit** (covers ≥ 2 points).

This is analogous to a classic **stars-and-bars** style argument: if we think of the `2k` endpoints as a **non-decreasing sequence** (allowing ties exactly where segments touch), we can shift each endpoint by its index to convert the "non-decreasing with limited repeats" sequence into a **strictly increasing** sequence over an extended range. This standard bijection technique transforms the counting problem into choosing `2k` elements from a set of size `n + k - 1`, giving:

```text
C(n + k - 1, 2k)
```

## Implementation Steps

1. Precompute factorials (and modular inverse factorials) up to `n + k - 1` using **Fermat's Little Theorem** for modular inverses (since `10^9 + 7` is prime).
2. Compute the binomial coefficient:
   ```text
   C(n + k - 1, 2k) = fact[n+k-1] * invFact[2k] * invFact[n-k-1] mod (10^9+7)
   ```
3. Return the result as a regular number.

Since intermediate factorial products can be extremely large, we use **BigInt** arithmetic throughout to avoid precision issues, then convert to a `number` only at the end.

---

# Complexity

- **Time complexity:** 
$$O(n + k)$$
for precomputing factorials and inverse factorials up to `n + k - 1`.

- **Space complexity:** 
$$O(n + k)$$
for storing factorial and inverse factorial arrays.

# Code

```typescript
function numberOfSets(n: number, k: number): number {
    const MOD = 1000000007n;
    const maxN = n + k; // we need up to n + k - 1

    const fact = new Array<bigint>(maxN + 1);
    const invFact = new Array<bigint>(maxN + 1);

    fact[0] = 1n;
    for (let i = 1; i <= maxN; i++) {
        fact[i] = (fact[i - 1] * BigInt(i)) % MOD;
    }

    const modpow = (base: bigint, exp: bigint, mod: bigint): bigint => {
        let result = 1n;
        base = base % mod;
        while (exp > 0n) {
            if (exp & 1n) {
                result = (result * base) % mod;
            }
            exp >>= 1n;
            base = (base * base) % mod;
        }
        return result;
    };

    invFact[maxN] = modpow(fact[maxN], MOD - 2n, MOD);
    for (let i = maxN - 1; i >= 0; i--) {
        invFact[i] = (invFact[i + 1] * BigInt(i + 1)) % MOD;
    }

    const nCr = (N: number, R: number): bigint => {
        if (R < 0 || R > N) return 0n;
        return (fact[N] * invFact[R] % MOD) * invFact[N - R] % MOD;
    };

    const totalN = n + k - 1;
    const chooseR = 2 * k;

    const result = nCr(totalN, chooseR);

    return Number(result);
};

```
