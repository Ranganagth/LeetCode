# Intuition

For a subarray to become **non-decreasing** using only increments, each element must be at least the previous adjusted element.

For example:

```text
[6, 3, 1, 2]
```

The cheapest non-decreasing version is:

```text
[6, 6, 6, 6]
```

Required operations:

```text
0 + (6 - 3) + (6 - 1) + (6 - 2) = 12
```

More generally, for a subarray, the optimal adjusted value at each position is its **prefix maximum**:

```text
adjusted[i] = max(adjusted[i - 1], nums[i])
```

The challenge is computing this cost for all subarrays efficiently. Recalculating prefix maximums for every subarray would be too slow.

We use:

- A **sliding window** to maintain the largest valid window.
- A **monotonic deque of groups** to maintain the prefix-maximum shape and its adjustment cost.

---

# Approach

## 1. Process subarrays from right to left

Maintain a current window:

```text
[left ... right]
```

For every `left`, extend the window by adding `nums[left]`.

The deque stores groups of equal values in the transformed non-decreasing array.

For example, if the current window is:

```text
[6, 3, 1, 2, 4]
```

Its minimum non-decreasing transformed form is:

```text
[6, 6, 6, 6, 6]
```

The deque stores:

```text
[(6, 5)]
```

where `(value, count)` means that `count` positions currently have adjusted value `value`.

---

## 2. Adding a new element on the left

Suppose we prepend `x`.

```text
Current transformed values: [3, 3, 5, 5]
Prepend x = 4
```

To remain non-decreasing, the beginning values smaller than `4` must become `4`:

```text
Before: [3, 3, 5, 5]
After: [4, 4, 5, 5]
```

This adds:

```text
(4 - 3) * 2 = 2
```

operations.

So, while the first deque group has value smaller than `x`:

- Remove that group.
- Add `(x - groupValue) * groupCount` to the cost.

Then add `x` as the new first group.

---

## 3. Shrink when cost exceeds `k`

If the transformation cost becomes greater than `k`, remove elements from the **right** side of the window.

The last adjusted value is stored in the deque's last group.

Removing `nums[right]` decreases cost by:

```text
adjustedValueAtRight - nums[right]
```

Then decrement that last group's count.

Keep shrinking until:

```text
cost <= k
```

---

## 4. Count valid subarrays

After fixing the window for a given `left`, every subarray:

```text
[left...left]
[left...left+1]
...
[left...right]
```

is valid.

There are:

```text
right - left + 1
```

such subarrays.

Add this to the answer.

---

# Complexity

- **Time:** $$O(n)$$

Each element/group enters and leaves the deque at most once.

- **Space:** $$O(n)$$

The deque can contain at most `n` groups.

---

# Code

```typescript
function countNonDecreasingSubarrays(nums: number[], k: number): number {
    const n = nums.length;

    // Deque of [adjustedValue, numberOfPositions].
    const values = new Array<number>(2 * n + 5);
    const counts = new Array<number>(2 * n + 5);

    let head = n;
    let tail = n - 1; // Empty when head > tail.

    let right = n - 1;
    let cost = 0;
    let answer = 0;

    for (let left = n - 1; left >= 0; left--) {
        const value = nums[left];

        /*
          Add nums[left] to the front.

          Any leading adjusted values smaller than `value`
          must be raised to `value`.

          Important:
          Their positions do not disappear. They become part
          of the new group whose adjusted value is `value`.
        */
        let mergedCount = 1;

        while (head <= tail && values[head] < value) {
            cost += (value - values[head]) * counts[head];
            mergedCount += counts[head];
            head++;
        }

        // Merge with an existing equal-value group if possible.
        if (head <= tail && values[head] === value) {
            counts[head] += mergedCount;
        } else {
            head--;
            values[head] = value;
            counts[head] = mergedCount;
        }

        /*
          Shrink from the right until the required increments
          are at most k.
        */
        while (cost > k) {
            const adjustedValue = values[tail];

            // Cost contributed by nums[right].
            cost -= adjustedValue - nums[right];

            counts[tail]--;

            if (counts[tail] === 0) {
                tail--;
            }

            right--;
        }

        // Every [left...end], where end <= right, is valid.
        answer += right - left + 1;
    }

    return answer;
};

```

# Example Walkthrough

## Input

```text
nums = [6, 3, 1, 3, 6]
k = 4
```

We process from right to left.

| `left` | Current window | Minimum transformed form | Cost | Valid subarrays added |
|---:|---|---|---:|---:|
| 4 | `[6]` | `[6]` | `0` | `1` |
| 3 | `[3,6]` | `[3,6]` | `0` | `2` |
| 2 | `[1,3,6]` | `[1,3,6]` | `0` | `3` |
| 1 | `[3,1,3,6]` | `[3,3,3,6]` | `2` | `4` |
| 0 | `[6,3,1,3,6]` | `[6,6,6,6,6]` | `11` | Too expensive |

At `left = 0`, the window needs `11` operations, but `k = 4`.

Remove from the right:

```text
[6,3,1,3,6] -> [6,3,1,3]
```

Cost becomes:

```text
(6 - 3) + (6 - 1) + (6 - 3) = 11
```

Still too expensive.

Remove from the right again:

```text
[6,3,1,3] -> [6,3,1]
```

Cost:

```text
(6 - 3) + (6 - 1) = 8
```

Still too expensive.

Remove from the right once more:

```text
[6,3,1] -> [6,3]
```

Cost:

```text
6 - 3 = 3
```

Now valid because:

```text
3 <= 4
```

So only these two subarrays starting at index `0` are valid:

```text
[6]
[6, 3]
```

Total valid subarrays:

```text
1 + 2 + 3 + 4 + 2 = 12
```

**Output:** `12`
