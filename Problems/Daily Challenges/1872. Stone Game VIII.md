# Intuition

This problem has a beautiful mathematical reduction. Since `x > 1`, whenever a player removes stones and replaces them with their sum, the **new stone's value equals a prefix sum** of the original array up to that point. This means every possible move corresponds to selecting an index `j` in the original array, and the score gained is always `prefixSum[j]`.

**Key insight:** The entire game reduces to choosing a strictly **increasing sequence of indices** from `[1, n-1]` (0-indexed), where the last chosen index must be `n-1` (since the game only ends when all stones are merged into one). Alice and Bob alternate turns, and whoever picks index `j` gains `prefixSum[j]` for their score.

---

# Approach

## Mathematical Reduction

If a player picks the first `k+1` stones (0-indexed up to `k`), their score gain is `prefixSum[k]`. The array then becomes `[prefixSum[k], stones[k+1], ..., stones[n-1]]`. 

When the next player picks `m` stones from this new array, their gain equals `prefixSum[k] + sum(stones[k+1..k+m-1]) = prefixSum[k+m-1]`.

So **every move's value is simply `prefixSum[j]`** for some index `j`, and consecutive moves must pick **strictly increasing** indices from `{1, 2, ..., n-1}`, with the final index always being `n-1` (game ends only when all stones are consumed).

## Dynamic Programming Formulation

Define `dp[i]` = the best achievable **score difference** (current player - opponent) when the next move must select an index from `[i, n-1]`.

**Recurrence:**
```
dp[i] = max(prefixSum[i] - dp[i+1], dp[i+1])
```

This represents two choices for the current player:
1. **Pick index `i` now:** Gain `prefixSum[i]`, then opponent plays optimally on `[i+1, n-1]`, giving difference `prefixSum[i] - dp[i+1]`
2. **Skip index `i`:** Move consideration to `i+1` while still being the current player's turn, giving difference `dp[i+1]`

**Base case:** `dp[n-1] = prefixSum[n-1]` (forced choice, no alternative)

**Answer:** `dp[1]` (Alice's first possible choice starts at index 1, since `x > 1`)

---

# Complexity

**Time Complexity:** $O(n)$
- Single pass to compute prefix sums
- Single backward pass to compute DP values

**Space Complexity:** $O(n)$ for prefix sum array (can be optimized to O(1) extra space if computed carefully, but $O(n)$ is simple and clear)

# Code

```typescript
function stoneGameVIII(stones: number[]): number {
    const n = stones.length;
    
    // Compute prefix sums
    const prefixSum: number[] = new Array(n);
    prefixSum[0] = stones[0];
    for (let i = 1; i < n; i++) {
        prefixSum[i] = prefixSum[i - 1] + stones[i];
    }
    
    // dp represents the best score difference for current player
    // starting from index n-1 (forced last move)
    let dp = prefixSum[n - 1];
    
    // Iterate backward from n-2 down to 1
    for (let i = n - 2; i >= 1; i--) {
        dp = Math.max(prefixSum[i] - dp, dp);
    }
    
    return dp;
};

```

## Solution with Detailed Comments

```typescript
function stoneGameVIII(stones: number[]): number {
    const n = stones.length;
    
    // Step 1: Compute prefix sums
    // prefixSum[i] represents the value obtained if a player merges
    // the first (i+1) stones into one
    const prefixSum: number[] = new Array(n);
    prefixSum[0] = stones[0];
    for (let i = 1; i < n; i++) {
        prefixSum[i] = prefixSum[i - 1] + stones[i];
    }
    
    // Step 2: DP from the end
    // dp represents: best score difference (current player - opponent)
    // achievable when next move can be any index >= current position
    
    // Base case: at the last possible index (n-1), the move is forced
    // (no choice but to take it, since this ends the game)
    let dp = prefixSum[n - 1];
    
    // Step 3: Work backward through possible starting positions
    for (let i = n - 2; i >= 1; i--) {
        // Current player's choice:
        // Option A: Take index i now, opponent then plays optimally on [i+1, n-1]
        // Result: prefixSum[i] - dp (dp represents opponent's best diff)
        // Option B: Skip index i, still current player's turn at i+1
        // Result: dp (unchanged, same as considering i+1)
        dp = Math.max(prefixSum[i] - dp, dp);
    }
    
    // dp[1] is our answer since valid moves start at index 1 (x > 1 means k >= 1)
    return dp;
};

```

# Example Walkthrough

## Example 1: `stones = [-1,2,-3,4,-5]`

### Step 1: Compute Prefix Sums

```
Index: 0 1 2 3 4
Value: -1 2 -3 4 -5

prefixSum[0] = -1
prefixSum[1] = -1 + 2 = 1
prefixSum[2] = 1 + (-3) = -2
prefixSum[3] = -2 + 4 = 2
prefixSum[4] = 2 + (-5) = -3
```

### Step 2: DP Backward Pass

```
Initialize: dp = prefixSum[4] = -3

i=3: dp = max(prefixSum[3] - dp, dp)
        = max(2 - (-3), -3)
        = max(5, -3)
        = 5

i=2: dp = max(prefixSum[2] - dp, dp)
        = max(-2 - 5, 5)
        = max(-7, 5)
        = 5

i=1: dp = max(prefixSum[1] - dp, dp)
        = max(1 - 5, 5)
        = max(-4, 5)
        = 5
```

### Final Answer

```
dp = 5
```

**Output:** `5` ✓

### Verification with Game Play

```
Alice picks index 3 (merges first 4 stones):
  Score = prefixSum[3] = 2
  Remaining: [2, -5]

Bob picks index 4 (merges remaining 2 stones):
  Score = -3 (which equals 2 + (-5))
  
Alice's score - Bob's score = 2 - (-3) = 5 ✓
```

# Visual Representation

## Game Reduction Concept

```
Original stones: [-1, 2, -3, 4, -5]

Every possible move corresponds to picking a "cut point":

Cut at index 1: score = prefixSum[1] = 1
Cut at index 2: score = prefixSum[2] = -2
Cut at index 3: score = prefixSum[3] = 2
Cut at index 4: score = prefixSum[4] = -3 (forced final cut)

Players alternately pick increasing cut points,
ending at index 4 (last stone position)
```

## DP State Transition

```
For each position i, the player decides:

        Position i
       / \
   Take it Skip it
      | |
  Gain prefixSum[i] Move to i+1
  Opponent plays (same player's turn)
  from i+1 
      | |
  Score: prefixSum[i] - dp[i+1] Score: dp[i+1]
      
  dp[i] = max(both options)
```

## Backward Computation Flow

```
n-1 (base) → n-2 → n-3 → ... → 1

Each step only depends on the next dp value,
allowing O(1) space if computed in reverse order
```

# Key Insights

1. **Prefix sum equivalence:** Every move's score gain equals a prefix sum of the original array, regardless of how many merges happened before
2. **Forced ending:** The game must end with the last index (`n-1`) being selected, as this is the only way to reduce to 1 stone
3. **Simple binary choice per position:** At each index, the current player either takes it (and lets opponent continue) or skips it (keeping their turn for later)
4. **$O(n)$ solution via DP:** Despite the complex-seeming game mechanics, the entire problem reduces to a simple linear DP
5. **Alice always starts at index 1:** Since `x > 1` means the first move must include at least 2 stones, corresponding to index ≥ 1

# Common Mistakes to Avoid

1. **Forgetting the forced ending:**
   ```typescript
   // Wrong: not recognizing that dp[n-1] is a base case with no choice
   let dp = 0; // Incorrect initialization
   
   // Correct: dp[n-1] must equal prefixSum[n-1] (forced)
   let dp = prefixSum[n - 1];
   ```

2. **Wrong recurrence direction:**
   ```typescript
   // Wrong: computing forward instead of backward
   for (let i = 1; i < n; i++) { ... }
   
   // Correct: must compute backward since dp[i] depends on dp[i+1]
   for (let i = n - 2; i >= 1; i--) { ... }
   ```

3. **Incorrect final answer index:**
   ```typescript
   // Wrong: returning dp[0] or dp[n-1]
   return dp[0];
   
   // Correct: return dp[1] since valid moves start at index 1 (x>1)
   return dp; // (which represents dp[1] after the loop)
   ```

4. **Not considering the "skip" option:**
   ```typescript
   // Wrong: always taking the current index
   dp = prefixSum[i] - dp;
   
   // Correct: consider both taking and skipping
   dp = Math.max(prefixSum[i] - dp, dp);
   ```
