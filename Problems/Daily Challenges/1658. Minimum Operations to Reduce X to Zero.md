# Intuition

Removing elements from the left and right ends until `x` becomes exactly `0` is equivalent to finding a **contiguous middle subarray** that we *keep* - one whose sum equals `total - x`. Maximizing the length of this kept subarray minimizes the number of removed elements (which is exactly the number of operations).

This transforms the problem into a classic **sliding window** task: find the **longest subarray** with a given target sum.

---

# Approach

1. Compute `total = sum(nums)`.
2. Compute `target = total - x`.
   - If `target < 0`, it's impossible to reach `x` (since all elements are positive, we can't remove enough to make `x` negative in total value) → return `-1`.
   - If `target === 0`, the entire array must be removed → return `nums.length`.
3. Use a **sliding window** (two pointers) to find the **maximum length subarray** with sum exactly equal to `target`:
   - Expand the window by moving `right`.
   - While the window sum exceeds `target`, shrink from `left`.
   - Whenever the window sum equals `target`, update `maxLen = max(maxLen, right - left + 1)`.
4. If no valid subarray was found (`maxLen` remains uninitialized), return `-1`.
5. Otherwise, return `nums.length - maxLen` (elements removed = total length minus the longest kept subarray).

---

# Complexity

- **Time complexity:** 
$$O(n)$$
Standard two-pointer sliding window — both `left` and `right` traverse the array at most once each.

- **Space complexity:** 
$$O(1)$$
Only a few scalar variables are used besides the input array.

---

# Code

```typescript
function minOperations(nums: number[], x: number): number {
    const n = nums.length;
    const total = nums.reduce((a, b) => a + b, 0);
    const target = total - x;

    if (target < 0) {
        return -1;
    }
    if (target === 0) {
        return n;
    }

    let maxLen = -1;
    let windowSum = 0;
    let left = 0;

    for (let right = 0; right < n; right++) {
        windowSum += nums[right];

        while (windowSum > target && left <= right) {
            windowSum -= nums[left];
            left++;
        }

        if (windowSum === target) {
            maxLen = Math.max(maxLen, right - left + 1);
        }
    }

    return maxLen === -1 ? -1 : n - maxLen;
};

```

# Example Walkthrough

## Example 1

```text
nums = [1,1,4,2,3], x = 5
```

- `total = 11`, `target = 11 - 5 = 6`

Sliding window search for subarray summing to `6`:
- Window `[4,2]` (indices 2-3): sum = 6 → length 2
- Window `[1,1,4]` (indices 0-2): sum = 6 → length 3 (better)

`maxLen = 3`

```text
answer = n - maxLen = 5 - 3 = 2
```

Output: `2` (matches: remove last two elements `[2,3]`)

## Example 2

```text
nums = [5,6,7,8,9], x = 4
```

- `total = 35`, `target = 35 - 4 = 31`

No subarray sums to exactly `31` (max possible subarray sum less than removing all is smaller than needed, and full array sum is 35 ≠ 31 for any contiguous slice)... Let's verify: sliding window would never hit exactly `31` since all combinations of contiguous sums don't equal `31` given the values. 

`maxLen` remains `-1`.

Output: `-1`

## Example 3

```text
nums = [3,2,20,1,1,3], x = 10
```

- `total = 30`, `target = 30 - 10 = 20`

Sliding window search for subarray summing to `20`:
- Single element `[20]` (index 2): sum = 20 → length 1

Checking other windows: no longer subarray sums to exactly `20` (adding neighbors like `3,2,20` = 25 too much, `20,1` = 21 too much, `20,1,1` = 22 too much).

`maxLen = 1`

```text
answer = n - maxLen = 6 - 1 = 5
```

Output: `5` (matches: remove first two `[3,2]` and last three `[1,1,3]`, keeping just `[20]`)
