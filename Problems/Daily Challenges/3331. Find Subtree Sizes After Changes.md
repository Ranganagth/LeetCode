# Intuition

For every node `x`, we need the **closest ancestor** `y` (in the *original* tree) whose character matches `s[x]`. If such a `y` exists, `x` gets reparented to `y`; otherwise `x` keeps its original parent.

Instead of literally rebuilding the tree and then computing subtree sizes, we can do both steps **simultaneously** in a single DFS:

- While walking down from the root, keep track of the **most recent node seen for each character** along the current root-to-node path. This directly gives us the closest same-character ancestor.
- While walking back up (post-order), we already know each node's *new* parent, so we can immediately add its finished subtree size into that parent's size — building the final sizes bottom-up without ever constructing the new tree explicitly.

Since `n` can be up to `10^5`, recursion could cause a stack overflow on a skewed tree, so the DFS is implemented **iteratively** using an explicit stack with an "enter/exit" trick (`x` to enter, `~x` to signal leaving `x`).

---

# Approach

## 1. Build the tree structure
For every node `x` from `1` to `n-1`, add `x` to `children[parent[x]]`.

## 2. Track nearest same-character ancestor (`above[]`)
Maintain `last[c]`, the deepest node with character `c` on the current root-to-node path.

- **On entering `x`:**
  ```text
  above[x] = last[charOf(x)] // closest ancestor with same character (or -1)
  last[charOf(x)] = x // x is now the deepest node with this character
  ```

- **On leaving `x`** (post-order), restore the state so sibling subtrees aren't affected:
  ```text
  last[charOf(x)] = above[x]
  ```

This is the classic "undo on backtrack" pattern for ancestor-tracking in iterative DFS.

## 3. Simulate the iterative DFS using enter/exit markers
Push `x` to process it (enter), and push `~x` (a negative sentinel) to mark when we should finish it (exit), pushing all of `x`'s children in between. Popping `~x` later means all of `x`'s children have been fully processed.

## 4. Accumulate subtree sizes on exit
When we finish node `x` (`pop ~x`):

```text
effectiveParent = above[x] >= 0 ? above[x] : parent[x]
size[effectiveParent] += size[x] // skip this for the root
```

Because children are always finished (popped as `~child`) before their parent, by the time we finish `x`, `size[x]` already correctly includes everything that was reparented onto `x`.

## 5. Return `size`

---

# Complexity

Let `n` be the number of nodes.

- **Time complexity:** `O(n)` — each node is pushed/popped a constant number of times, and character bookkeeping is `O(1)` per step.
- **Space complexity:** `O(n)` — for `children`, `size`, `above`, the stack, and `last` (constant size `26`).

---

# Code

```typescript
function findSubtreeSizes(parent: number[], s: string): number[] {
    const n = parent.length;

    // Build adjacency list of children.
    const children: number[][] = Array.from({ length: n }, () => []);
    for (let x = 1; x < n; x++) children[parent[x]].push(x);

    const size: number[] = new Array(n).fill(1);
    const above: number[] = new Array(n);

    // last[c]: deepest node with character c on the current root-to-node path.
    const last: number[] = new Array(26).fill(-1);

    // x >= 0 means "enter x", ~x means "leave x" (iterative DFS, avoids recursion).
    const stack: number[] = [0];

    while (stack.length) {
        let x = stack.pop()!;

        if (x >= 0) {
            // Entering x.
            const c = s.charCodeAt(x) - 97;
            above[x] = last[c]; // closest same-character ancestor, or -1
            last[c] = x;

            stack.push(~x); // mark to process x again after its children
            for (const child of children[x]) stack.push(child);
        } else {
            // Leaving x.
            x = ~x;
            last[s.charCodeAt(x) - 97] = above[x]; // restore ancestor state

            if (x > 0) {
                // Attach x's finished subtree size to its effective new parent.
                const effectiveParent = above[x] >= 0 ? above[x] : parent[x];
                size[effectiveParent] += size[x];
            }
        }
    }

    return size;
};

```

# Example Walkthrough

## Example 1

```text
parent = [-1, 0, 0, 1, 1, 1]
s = "a b a a b c"
            0 1 2 3 4 5
```

**Tree structure:**
```text
0
├── 1
│ ├── 3
│ ├── 4
│ └── 5
└── 2
```

### DFS trace (character codes: a=0, b=1, c=2)

| Step | Action | `above[x]` | `last[]` after | `size` updates |
|---|---|---|---|---|
| Enter 0 (`a`) | `above[0]=-1` | `last[0]=0` | — |
| Enter 2 (`a`) | `above[2]=0` | `last[0]=2` | — |
| Leave 2 | restore `last[0]=0` | | `size[0] += size[2]` → `size[0]=2` |
| Enter 1 (`b`) | `above[1]=-1` | `last[1]=1` | — |
| Enter 5 (`c`) | `above[5]=-1` | `last[2]=5` | — |
| Leave 5 | restore `last[2]=-1` | | effective parent = `parent[5]=1` → `size[1]=2` |
| Enter 4 (`b`) | `above[4]=1` | `last[1]=4` | — |
| Leave 4 | restore `last[1]=1` | | effective parent = `above[4]=1` → `size[1]=3` |
| Enter 3 (`a`) | `above[3]=0` | `last[0]=3` | — |
| Leave 3 | restore `last[0]=0` | | effective parent = `above[3]=0` → `size[0]=3` |
| Leave 1 | restore `last[1]=-1` | | effective parent = `parent[1]=0` → `size[0]=6` |
| Leave 0 | (root, skip) | | |

### Final sizes

```text
size = [6, 3, 1, 1, 1, 1]
```

Matches expected output `[6,3,1,1,1,1]` — node `3`'s parent changed from `1` to `0` (since `s[3]='a'` matches `s[0]='a'`, which is closer than through node 1).

## Example 2

```text
parent = [-1, 0, 4, 0, 1]
s = "a b b b a"
            0 1 2 3 4
```

**Tree structure:**
```text
0
├── 1
│ └── 4
│ └── 2
└── 3
```

Following the same enter/exit logic:

- Node `3` (`b`): no ancestor with `'b'` yet → keeps original parent `0`.
- Node `2` (`b`): closest ancestor with `'b'` is node `1` (skipping node `4`, whose character is `'a'`) → reparented to `1`.
- Node `4` (`a`): closest ancestor with `'a'` is node `0` → reparented to `0`.
- Node `1` (`b`): no ancestor with `'b'` → keeps original parent `0`.

### Final sizes

```text
size = [5, 2, 1, 1, 1]
```

> Matches expected output `[5,2,1,1,1]` — exactly reflecting that node `4`'s parent becomes `0`, and node `2`'s parent becomes `1`.
