# Intuition

Since we're allowed to **change two elements to anything we want**, the smartest strategy is to set both changed elements to the **same value already present** in the array (or any value that matches another element) — this makes the **low score exactly `0`** (since `|x - x| = 0`).

With the low score eliminated, the problem reduces to: **minimize the high score (the range) of the remaining array after effectively "removing" the influence of two elements.**

Since we can freely reassign two elements, we should think of it as choosing which two elements to "sacrifice" (turn into duplicates of other values) so that the **remaining elements' range is as small as possible**. After sorting, the extremes (smallest and largest values) are the primary contributors to a large range, so the optimal strategy is to eliminate values from one or both ends of the sorted array.

---

# Approach

1. **Sort** the array.
2. There are three strategic ways to eliminate the effect of 2 elements on the range:
   - **Remove the two largest elements** → the new max becomes `nums[n-3]`, min stays `nums[0]` → range = `nums[n-3] - nums[0]`.
   - **Remove the two smallest elements** → the new min becomes `nums[2]`, max stays `nums[n-1]` → range = `nums[n-1] - nums[2]`.
   - **Remove one from each end** → new range = `nums[n-2] - nums[1]`.
3. Since the two changed elements can be set equal to some other existing value in the array (contributing `0` to the low score), the **final answer is simply the minimum of these three possible ranges** (the high score), since low score is always achievable as `0`.
4. Return the minimum among these three candidate values.

### Why this works
By sorting, the array's range is governed by its extreme elements. Since we control exactly 2 values, we can "neutralize" up to 2 extreme contributors — either both from the top, both from the bottom, or one from each side. Testing these three configurations covers all optimal possibilities, because removing non-extreme elements would never reduce the range more than removing extremes would.

---

# Complexity

- **Time complexity:** $O(n log n)$ — dominated by sorting.
- **Space complexity:** $O(1)$ extra space (or $O(log n)$ / $O(n)$ depending on the sort implementation's internal overhead), since no additional data structures are required beyond the input array.

---

# Code

```typescript
function minimizeSum(nums: number[]): number {
    nums.sort((a, b) => a - b);

    const n = nums.length;

    // Option 1: Remove the two largest elements.
    const removeTwoLargest = nums[n - 3] - nums[0];

    // Option 2: Remove the two smallest elements.
    const removeTwoSmallest = nums[n - 1] - nums[2];

    // Option 3: Remove one from each end.
    const removeOneEach = nums[n - 2] - nums[1];

    return Math.min(removeTwoLargest, removeTwoSmallest, removeOneEach);
};

```

# Example Walkthrough

## Example 1

```text
nums = [1, 4, 7, 8, 5]
```

Sorted: `[1, 4, 5, 7, 8]`, `n = 5`

- **Remove two largest:** `nums[2] - nums[0] = 5 - 1 = 4`
- **Remove two smallest:** `nums[4] - nums[2] = 8 - 5 = 3`
- **Remove one each end:** `nums[3] - nums[1] = 7 - 4 = 3`

Minimum: `3`

Output: `3`

This matches the example — changing two elements to `6` (e.g., turning `1` and `4` into `6`s) leaves `[5, 6, 6, 7, 8]`-like structure with range `3` (between `5` and `8`) and low score `0`.

## Example 2

```text
nums = [1, 4, 3]
```

Sorted: `[1, 3, 4]`, `n = 3`

- **Remove two largest:** `nums[0] - nums[0] = 1 - 1 = 0`
- **Remove two smallest:** `nums[2] - nums[2] = 4 - 4 = 0`
- **Remove one each end:** `nums[1] - nums[1] = 3 - 3 = 0`

Minimum: `0`

Output: `0`

This matches — changing two elements to `1` gives `[1, 1, 1]`, with both low and high scores equal to `0`.
